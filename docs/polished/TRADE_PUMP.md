## End-to-end dev flow and event mapping

Proposer: poll QUERY -> `trade_query{}` -> `trade_mask` -> `answer_query(gen, mask, token4)`; poll OFFER -> `trade_offer{slot}` -> `trade_offer_ack{ok,token}` -> `answer_offer(gen,ok)`. Preserve the server token from the positive ACK separately from token4. Existing vanilla reference: `lua/gen2/client.lua:733-762,935-949`; server native offer/ACK: `server/state.py:994-1033`.

Responder, after the prerequisite extension: `show_menu{token,slot,blob_hex}` -> validated PROMPT arm -> poll phase-bound DONE -> release the exact PROMPT generation. Only a proved consent and successful release authorizes `menu_result{token,choice:1}`; decline produces choice 0. The ROM must consume PROMPT RELEASE before APPLY publication; require at least the next frame end and revalidate that RELEASE is still the matching visit. This is distinct from the proposer's OFFER gap (`patch/polished/src/trade_responder.asm:14,25-30`). Current vanilla reference is `client.lua:767-784,899-904`.

Preparation: `apply_prepare{token,slot,old_key}` records one pending prepare and checks accepted visit, exact server token, current full key/slot, role, epoch, nonpoisoned open lease, and the applicable frame gap. It stages nothing. Hold a same-frame prepare until the next eligible tick; send `apply_ready{token,ok:true}` only after checks pass, otherwise false. Existing checks are at `client.lua:790-795`; server requires the exact token and both ready replies at `server/state.py:1218-1248`. A readiness reply is not a commit witness.

Payload seam: Polished requires `{blob, sender}` with validated byte arrays (`lua/gen2/polished_trade.lua:332-344`), whereas vanilla passes `{blob, partner_name}` (`lua/gen2/client.lua:814-815`) and encodes the name inside its binder (`lua/gen2/trade_overlay.lua:167-176`). The dev client must strictly decode the full 70-byte hex blob and encode the sender with the admitted Polished charmap and exact sender span; never pass a string as sender or silently skip malformed hex. PROMPT lacks partner_name in the existing client path, so the binder card must specify a validated OT-name fallback, matching the vanilla policy, or refuse; do not invent a new required server field. Exact Polished encoder reuse is UNVERIFIED and must be resolved in that card.

APPLY: accept only the matching accepted visit and immutable payload, park it when the frame gap has not elapsed, then call `arm(APPLY,slot,token4,payload)` once. Track the returned generation. Poll phase-bound DONE; release only a safe terminal disposition with its exact generation; wait for close before resetting/reusing the binder. Commit-disabled end-to-end success means both sides report NOT_PERFORMED and the server retains the old link, never a completed swap.

## Frame gap, identity, and queued-command contract

At OFFER answer frame F, publish only its ACK/result. Do not publish APPLY until a tick with `io.framecount() > F`, after an intervening emulated frame. Store `offer_answer_frame` only when answer_offer succeeds. The binder already enforces this (`lua/gen2/polished_trade.lua:393-418`). A command arriving alongside ACK is parked without a write and without a terminal server event; the next dev tick rechecks everything before arm. Apply the analogous rule to responder PROMPT RELEASE. Do not move the vanilla tick or change reply draining to manufacture the gap.

Why this is needed: `client.lua:1931-1946` drains replies with infinite budget, while `:2430-2435` polls trade before dispatching replies. Vanilla's answer_offer immediately marks acceptance (`:752-758`); apply_trade immediately arms (`:799-821`). Server ACK can remain queued (`server/state.py:1030-1033`) until partner confirmation directly dispatches APPLY when either side lacks prepare (`:1194-1197,1336-1346`). Both commands can then arrive in one drain. Shared lease arm increments generation and publishes it (`lua/gb_trade_lease.lua:124-150`); vanilla WaitAck requires generation and ACK to equal the prior generation (`patch/gen2/src/trade_service.asm:444-453`). Thus the ROM can miss the OFFER answer. The prepare path normally adds a network pump because `connector.send` only queues (`lua/connector.lua:138-142`), but this scheduling accident is not a substitute for an explicit gap, especially under replay or batched injected commands.

Per-visit record: local monotonically increasing epoch; timeline/identity binding; role; four-byte ROM token; server token; query/OFFER/PROMPT/APPLY generations; slot and full old key; immutable command payload; accepted flag; answer/release frame; absolute deadline; whether arm emitted/attempted; terminal disposition/report state. Never equate eight-bit generation with identity. Generation wraps modulo 256 (`gb_trade_lease.lua:139`); reset/load invalidates the epoch, not just a counter. Reject stale/mismatched server tokens without touching the current visit. Duplicate matching commands are idempotent; a conflicting payload for the same token poisons/refuses rather than restaging. A second APPLY cannot replace a parked one. Preserve uncertainty on exceptions where write emission cannot be ruled out.

Timeouts use the original visit/pending-command deadline; reconnect, duplicate ACK, or PENDING must not restart it. An expired unarmed APPLY may report certain none only if no write/arm occurred; after an attempt use binder evidence, otherwise uncertainty. A queued withdrawal cancels an unarmed local APPLY; once armed, do not invent a missing binder withdraw method or write lease bytes directly. Retain the attempt for polling and eventual uncertainty.

The countdown issue is separate: vanilla decrements before inspection (`patch/gen2/src/trade_service.asm:210-223`), and its test pins the exclusive last frame (`tests/unit/test_gen2_trade_service.py:633-647`). Current Polished inspects before expiry (`patch/polished/src/trade_service.asm:145-158`). Do not change either ROM or import vanilla's shortened deadline into Polished as part of C4b.

## Host cancel of a pre-APPLY visit (card g2p-cancel, 2026-10-08)

Implemented, not design: `lua/gen2/polished_trade.lua` `T:cancel(reason)` with `tests/unit/test_polished_trade_binder.py` (the real proposer and responder service bytes on the SM83 rig, 25 cases, 5 red controls). Owner ruling 2026-10-07 applies: uncertainty BEFORE an APPLY is armed closes the lease, logs once and reports NOT_PERFORMED; UNCERTAIN stays reserved for an armed APPLY, whose path is unchanged.

**Lease bytes.** A cancel writes only what the ROM already names as a host-side close (`patch/polished/src/trade_service.asm:20-21`): the four visit-token bytes (+12..15) are zeroed, and an OFFER that is still unanswered is rejected first (+8 result 1, then +7 ACK = its generation LAST, the same bytes as `answer_offer(gen,false)`; `trade_service.asm:145-147` exits on any nonzero result). Command (+5) and generation (+6) are never written: a cancel cannot be read as PROMPT, APPLY, RELEASE, consent or a commit. `SlinkTradeCheckToken` refuses a zero token (`trade_frame.asm:50,69-71`) at every pre-APPLY inspection of both services - proposer `trade_service.asm:81` (after the QUERY answer, before the party menu), `:114` (`CheckHeldFrame` after the native menus, before the snapshot and the OFFER), `:140` (after the OFFER answer), `:166` (every APPLY-wait frame); responder `trade_responder.asm:70` (entry), `:106` (after the YesNoBox, before the consent snapshot/DONE), `:150` (every RELEASE-owed / APPLY-wait frame) - and each refusal is `jp SlinkTradeExit` / `SlinkTradeResponderExit` (snapshot released, `SlinkTradeClose`, balanced stack, no DONE). A RELEASE or a command 0 would NOT close the APPLY wait (`trade_service.asm:168-170` ignores every command but APPLY), which is why neither is the close. The post-DONE 90-frame holds ignore the token (`trade_service.asm:227-229`, `trade_responder.asm:227-229`) and close by themselves; a responder NO pressed after the cancel still publishes its decline DONE (`:128-131`), which `poll_done` no longer claims. Every write is read back through the shared lease verification; a readback mismatch or partial emission latches UNCERTAIN as on every other write path.

**Binder contract.** `cancel(reason)` with a non-empty string reason. Returns `true` on success (idempotent: a second call writes and logs nothing). Refusals write nothing: `nil,'PENDING','no visit to cancel'` (no QUERY answered / no PROMPT armed), `nil,'PENDING','cancel reason required'`, `nil,'PENDING','APPLY already armed: cancel refused'` (`attempted` is set; that visit belongs to the ROM), `nil,<disposition>,'visit already terminal: ...'` (offer rejected, prompt DECLINED, or a commit-disabled DONE already observed; `release()` is their path), `nil,'UNCERTAIN',why` when poisoned. Allowed phases: proposer `query` (menu or unanswered OFFER) and `offer` (accepted, ROM waiting for APPLY); responder `prompt`, `consented` (RELEASE still owed) and `released`. After success: `phase()` is `role,'cancelled'`, `disposition()` is `'NOT_PERFORMED','cancelled before APPLY: <reason>'`, `poll_query/poll_offer/poll_done` return nil, `answer_*`/`arm`/`release` refuse with `NOT_PERFORMED`, and `reset()` is allowed once `closed()` is true - the binder is then reusable (proved on the rig: a cancelled accepted-OFFER visit followed by a full `QOADC` visit on the same binder; a cancelled responder visit followed by a fresh PROMPT arm on the ROM's closed lease). The log line is `[SLink-polished] trade visit cancelled before APPLY (<role>/<phase>): <reason>` through `spec.log` (production composition passes none, so it is the console `print`).

**arm(APPLY) fault before publication (coordinator addition).** When an arm emits writes and then fails (a staging byte, or the frame bytes before the command byte) and the readback proves the lease is still the exact held pre-APPLY frame (accepted OFFER / consumed consent RELEASE: header, token, slot, result 0, generation == ACK), the binder now takes the cancel path itself and returns `nil,'NOT_PERFORMED','cancelled before APPLY: APPLY not published: <error>'` (lease closed by the ROM on its next inspection, logged once, reusable after close). Anything the readback cannot prove - the APPLY command byte or generation observed, or an unreadable lease - stays UNCERTAIN/poisoned (no cancel, no reset; the ROM's own hold closes). Both halves run on the real proposer service (`test_real_arm_fault_halves`); the responder APPLY path takes the same branch (unit-covered).

**What the pump should call (another worker owns `lua/gen2/client.lua`; nothing here edits it).** In `install_dev_trade_pump`, inside `finish(why, uncertain, after_reset)` before the server report, when `not v.attempted` and the binder visit exists (a `v.gen` was obtained, i.e. `answer_query` succeeded or a PROMPT was armed): `local ok, kind, detail = call("cancel", why)`; treat `kind == "UNCERTAIN"` like every other UNCERTAIN (`v.retired = true`); any other refusal is informational (the ROM will close by itself or already has). Call sites that reach this: `withdraw_trade` (`client.lua:1133`), `D.forget("disconnected")`/identity or epoch change (`:1141-1142`), `D.stop()` shutdown (`:1222`), `finish("invalid query mask")`, `finish("parked trade identity changed")` (`:1189`), the deadline expiry (`:1179-1180`, only when not attempted) and any menu-left/server-declined path added later. Do not call it from `D.forget` when `v.attempted` is true, nor for `finish("offer declined")` / `finish("prompt declined")` (already terminal; the binder refuses harmlessly). The existing terminal-visit tick (`:1144-1148`: wait for `closed()`, then `reset()`) is exactly the post-cancel sequence and needs no change. Two pump lines must change for the arm-fault ruling: `:1192` sets `v.attempted = true` BEFORE `arm` and `:1196` reports uncertainty from that flag; with this binder an arm that returns `nil,'NOT_PERFORMED',...` has already closed the lease, so the pump must take `attempted` from the binder's answer (`gen ~= nil`, or `disposition()`), not from its own pre-set flag, and report `menu_result{choice:0,withdraw:true}` (proposer) / `menu_result{choice:0}` (responder) for it - never `trade_done{uncertain:true}`.
