## The two corrections this round makes to the round-2 record

1. **A play is an EDGE, not an equality.** `wCurSFX` is written in exactly one place
   (`home/audio.asm:265`, inside `PlaySFX`) and is never cleared when a sound ends — it is a sticky
   "last id" register. Round 2 asserted `wCurSFX == expected` on the first matching frame and never
   recorded the pre-post value, so it could not exclude a stale match. **Round 2's "check 2 PASS"
   is retracted to PARTIAL.** Every cue below now samples 30 frames pre-post, requires the expected
   id *not* already showing and the channel *not* already running, and only then accepts
   `wCurSFX == expected` **and** `SOUND_CHANNEL_ON` (`constants/audio_constants.asm:73`) together.
2. **`SOUND_CHANNEL_ON` is bit 0, so `$01` means the channel is ON.** Round 2 read a `$01`
   `wChannel5Flags` as "channel gone" and concluded the busy window was ~4 frames, then argued the
   hold test could not fire. That was wrong: the window is long (this run measures ~162 service
   visits), which is exactly what makes the hold observable.

The ids are **not pasted**: `sounds.lua` reads
`data/games/polished_crystal/profile.json` → `titles.polished.overlay.sfx.codes`
(`success 1 / failure 25 / boo 36 / notify 8`), generated by `tools/gen_polished_profile.py` from the
pinned `constants/sfx_constants.asm:4,11,28,39`. The ROM's own table is symbolic
(`patch/polished/src/slink_sfx.asm` `.sounds`: `db SFX_ITEM, SFX_WRONG, SFX_BUMP, SFX_READ_TEXT_2`),
so the driver and the ROM are two independent readings of the same four ids.
