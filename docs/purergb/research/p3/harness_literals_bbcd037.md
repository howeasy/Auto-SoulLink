## 4. What M2-e has to change (from the three tables)

1. **Two structural gaps that are not literals at all.** `gen1_rb_parcel_inputs.lua:40` resolves its per-title table with `assert(LAB[title])` and the table has no pure key, so a pure parcel leg dies on the first call rather than falling back. `gen1_rb_mart_signature.lua:29` falls back to `INVENTORY.red`, which happens to match pureRGB's stock — an unverified fallback that will read as green.
2. **The rival id and the START-menu convention are still vanilla in the tree** (`gen1_rb_ball_gate_inputs.lua:110`, `gen1_rb_route22_inputs.lua:110`, `gen1_rb_save_inputs.lua:62`). D2's own summary says the id was "already fixed by the harness"; the live literals say otherwise — the fix D2 validated was applied to a scratch copy, not to this tree.
3. **D2's gaps cluster in three areas it did not touch**: menu geometry beyond the battle/PC/START menus (party menu ×2, switch box, naming screen, Mart list), the poison and catch-rate mechanics (both left explicitly UNVERIFIED), and internal species ids (`WEEDLE=0x70`, starters 8/6) — the last one matters because pureRGB renumbers internal indices for its 13 non-dex records.
4. **The bank filter `hLoadedROMBank == 0x0F` (`gen1_battle_driver.lua:76`) is still a literal and still D2-UNVERIFIED.** The M1 pack gives the pure battle-engine bank; the driver should read it from the profile/facts rather than keep the constant.
5. **N-lane readiness is half-done.** Ports, data dir, and per-scenario receipts are parameterised; the generated stub and the BizHawk config copy are named per instance only (`duo_{inst}.lua`, `duo_cfg_{inst}.ini`), and the window position is one global value. Scaling to N lanes needs a lane id in those three names.
