## The callback is a snapshot, not an end-of-frame reread

[Lua collection](../../../lua/gen1_engine_signals.lua#L25) reads the entire 404-byte party region and battle/slot fields **inside** each execution callback, then appends that signal to `pending` (lines 52–65). `peek` returns a copy; `batch` copies the ordered list. The free [observation loop](../../../lua/gen1_observation_loop.lua#L76) publishes whenever signals exist, persists the event before draining them, and retains the list without sorting or replacing earlier party bytes (lines 103–135). Two callbacks in one emulated frame therefore still carry two different snapshots.

On the server, [engine batch validation](../../../server/gen1_engine_signals.py#L106) preserves list order and allows equal frames. [Engine staging](../../../server/gen1_engine_signal_runtime.py#L85) requires a contiguous signal sequence across batches and calls faint settlement on the full entry. [Observation staging](../../../server/gen1_observation_runtime.py#L185) uses that same path. [Faint settlement](../../../server/gen1_faint_runtime.py#L117) enumerates signals in order: it marks the current link DEAD, creates its own signal-derived death ID and physical obligation, then calls whiteout before proceeding to the next signal (lines 177–233). Logical death does not wait for the peer's physical ACK; storage may defer command issuance while preserving the death (lines 202–224).

Thus neither same-frame collection nor delayed network delivery moves a later all-zero snapshot onto an earlier signal. An earlier rejected observation cannot be silently skipped into an accepted later sequence under this path. This establishes source ordering; it does not prove actual callback delivery or scheduler liveness on the physical host.

## Sequential battle faints, including recoil/enemy-first resolution

`AnyPartyAlive` ORs each slot's HP ([R/B lines 1455–1470](../../../.cache/pret/pokered/engine/battle/core.asm#L1455), [Yellow lines 1494–1509](../../../.cache/pret/pokeyellow/engine/battle/core.asm#L1494)).
