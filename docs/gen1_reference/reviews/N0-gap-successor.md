## One exact gate design on unchanged source

This is a proposed implementation/physical assignment, not an execution receipt. Keep all gate logic in the one proposed Python file; no Lua wrapper, `run_gate`, RAM/save/state/CPU fixture, joypad route, patched launcher, monkeypatched client runtime, or direct call to `prepare`/`launch`.

1. Under a separately granted exclusive emulator lane, verify source/input pins, record process inventory and require no other emulator owner. Create a unique receipt directory `R/.cache/n0-product-cli-<unique>/` (`E` below). Use the existing real Manager HTTP POST with `native=true`, `start=false`, clean Yellow for both players; its canonical companion preparation remains the product path. Start the actual `SLinkServer` TCP handler with `open_runtime(run_directory)` and publish that listener port into this test Manager registry **before** downloading. This may run in the gate's process, as in `selected_manager`; it is not a claim that Manager's own service-process CLI was tested.
2. Download `/api/runs/<manager_id>/launcher/a?bundle=1` and `/b?bundle=1`. Preserve ZIP bytes/hash; require exactly `launch.json`, `launcher.lua`, `README.txt`; extract bytes under `E/downloads/a` and `E/downloads/b`. Require identical final Y ROM SHA1/SHA256 for the two run-local `prepared/final/{a,b}/slink_yellow.gb` files, correct player-specific manifests and their common actual runtime session `S`. Record source closure pins and listener address.
3. For the smallest **current-source** gate set `--root R`, where `R` is the canonical checkout. This gives unique private homes `R/S/a` and `R/S/b`, with generated script depth exactly three below `R`; the unchanged renderer can find the installation through `../../../`. Require `R/S` absent before the run, resolve containment, exclude junction/symlink aliases, and record ownership outside that new tree. This is an explicit test-root choice, not the default LocalAppData path and not a recommendation to relocate users' saves. The future live claim must reserve the exact generated `R/S` tree after Manager allocates S. Never precreate a fake launch marker or cache to bypass ownership checks.
4. Copy the verified host base config to `E/base-config.ini`; preserve source and copy hashes. Inspect that copy for unwanted automatic state/Lua loading before granting execution; this report has not validated the installed config's complete operational settings. The gate may configure this private base for clean startup, but must list every override and derive its supported meaning from the pinned host. Begin with both private SaveRAM roots absent; do not manufacture blank saves. Downloaded Lua/manifest bytes remain unchanged.
5. Spawn the following command arrays concurrently for players a and b using Python `subprocess.Popen`, redirecting each CLI's stdout/stderr to its own receipt files. The real CLI then spawns the pinned EmuHawk. Await bounded observations, proposed 60 seconds per pair; timeout is a failed/HOLD receipt, never a skip or implicit success. Do not automate opening gameplay to satisfy a missing oracle.

### Owned cleanup

Retain each spawned CLI process handle immediately. Discover only direct EmuHawk children whose parent is that exact CLI PID, executable matches the pin and creation time follows dispatch; obtain and retain their Windows process handles/creation identities before cleanup. On timeout or completion request normal window close for those owned child handles, wait at most five seconds, then terminate only those still-running owned child processes and record forced termination. Wait at most five seconds for each CLI to return; terminate only a still-owned CLI handle after its known child has exited. Never kill by executable name, sweep all EmuHawks, or terminate the CLI first and leave its child running without the player lease. If child identity cannot be established, report HOLD for coordinator intervention; do not guess a PID.

Close the gate-owned TCP listener/runtime/HTTP clients after child cleanup; preserve receipts, private generated homes, locks, saves and journals for review. No recursive deletion is needed. Nonzero exit caused by requested teardown is recorded as teardown, not a successful natural child exit or persistence receipt. OS handle release, not deleting `.process.lock`, releases the lease (`runtime_lease.py` lines 32–37).

## Missing oracle and separately claimable seam

**Required missing oracle:** a fresh external receipt after `M.start(launch)` succeeds and before the first `service:step()`/`frameadvance`, containing the existing host's verified early hold. `slink_path.cfg` is too early; server events/journal are too late; a running process and Python stdout are insufficient. This is a source-established observer gap, not an observed physical startup defect.

Small proposed separate claim: one writer for `lua/gen1_client_entry.lua` plus the existing `tests/unit/test_gen1_native_entry.py`, subject to native/D0b file-owner serialization. Publish a bounded, atomic startup-status file under the existing private session/player home from `M.run` immediately after successful `M.start`; reuse existing host status, without altering startup/hold/frame order. Suggested receipt fields: schema, run/player, resolved host PID, owner/physical nonce, observed frame, phase, final ROM SHA1, profile capability, lease ownership, `host_blocked`, `held`, `physical_stop_verified`, failure, and explicit `admitted=false`/`scope=pre-first-client-frame`. Bind freshness to the newly owned process and absent output, not a timestamp alone. Missing/unreadable/stale/wrong-player/wrong-PID/false-stop receipt must fail the physical gate. Source/closure pins remain supplied by the newly downloaded bundle; do not patch an old bundle to include changed client bytes. First model falsifier: unchanged entry does not publish that file; refusal cases must retain existing hold semantics and cannot emit a success receipt after failed startup.

That seam would enable **physical startup/early-hold** evidence only. It cannot make cold title-screen startup enrolled. Full N0's enrollment/reattach portion still requires an expressly assigned normal-input checkpoint and existing source-bound bootstrap/initial-save/reattach ACKs, or a separately designed equivalent observable route; this report grants neither. The N0 acceptance criterion must preserve that distinction.

A separate optional root-discovery fix is also source-concrete: consume/validate the CLI-provided environment `SLINK_ROOT` in `server/runtime_launcher.py` before falling back to the folder picker, with its renderer tests. This would permit `--root E/clients` without cached path seeding or an interactive dialog. It is **not a prerequisite** for the narrowly specified current-source `--root R` gate, and should not be bundled into the startup-status claim. Root discovery/relative script-path behavior still needs its first physical receipt; if that source hypothesis fails, stop at the actual dialog/error instead of modifying the launcher mid-run.
