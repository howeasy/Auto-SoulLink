## Product and finish line

The product is a playable two-person Red/Blue/Yellow Soul Link through the game: 1× at full FPS, the owner's accepted near-3× rate, correct paired acquisition/death/storage/evolution/PC behavior, an original-ROM native trade with both saved files, truthful interruption handling, and a usable Manager/bundle. This is Pokémon, not a general transaction research program. R/B companion cartridges have panel+trade; Yellow's companion is trade-only (no panel); SFX currently reports disabled for all three ([profiles](../../server/gen1_cartridge_profiles.py), [scope](../../tests/gen1_release_requirements.json)). Do not invent a Yellow panel or optional SFX feature.

The pre-human RC verdict is a frozen-source, non-quick `tools/verify_gen1_release.py` report with `automation_passed: true`: all 15 checks, eight pinned prerequisites, and 387 non-human requirements pass, with zero skips/xfails/deselection and no input drift. The 388th row is a separate two-person human session; `--complete-human` produces `release_passed` only afterward ([runner](../../tools/verify_gen1_release.py)). A green component suite, prior live receipt, or registered proof is not RC. Merging to `master`/shipping is an owner decision after the human verdict, not an automatic by-product of it.

## Dispatch rules and dependency graph

A package is one behavioral claim, preferably one to three production files and a bounded assertion/receipt. If it needs a new shared abstraction or a whole route driver, split it before coding. Each package carries `WAIT`, `READY`, `ACTIVE(owner,branch,files)`, `PROVED(receipt,commit)` or `HOLD(reason)` in the integrator's next guide update. **No implementation card is claimed at this handoff.** Current dispatch state: P0/F1 are READY for bounded read-only environment work; P1/P2a/P2b await owner policy; N0–R4 are WAIT for explicit B/native resumption and exact file assignment; C/D/E/T implementation is WAIT for separate owner go-ahead and its dependencies; F/H are WAIT for freeze/humans. No ACTIVE package. Read-only source mapping W0 is already done; do not repeat it.

A single integrator owns `gen1/rc`, shared runtime files, the manifest, and the one EmuHawk lane. Source/ROM research and test-scenario design may be parallel. Distinct agents may code in disjoint file sets/branches; `gen1_runtime.py`, `gen1_client_entry.lua`, `gen1_native_execution.py`, storage runtime, UPR pipeline, companion build, browser output bridge and D0 scenario core each have **one writer at a time** and an exact integrator-assigned file list. N native writer goes before C5/D0b on the overlapping client/runtime paths. A completed card is reviewed/merged before dependent code starts. Live runs queue separately; never overlap two EmuHawks with another measured job. An unchanged failure is diagnosed once, not rerun until source, oracle, or explicit policy changes. Official [Git worktree](https://git-scm.com/docs/git-worktree/2.42.1), [Claude worktree isolation](https://code.claude.com/docs/en/worktrees), and [small/stacked review](https://docs.github.com/en/pull-requests/get-started/about-pull-requests) guidance supports isolated edits and reviewable dependent cuts; it does **not** justify dozens of idle checkouts.

## Owner decisions and failure policy

- Clean idle same-run re-enrollment (P2a/D0b) and replaced-emulator partial-trade visible replay/re-enrollment (P2b/R3) are **different, unapproved decisions**. Saved-but-unwitnessed, rollback, missing/older native lease, wrong epoch, or unknown high-water **HOLD**. A repeated SavePartyAndDexData of identical bytes may be physically tolerable; a second RemovePokemon/AddEnemyMon is not. Neither peer agreement nor identical bytes authorize forward replay.
- An imported battery save in a new Manager run and loading an external savestate into a running selected run are refused by design. A user-made receptionist save is **not** selected evidence on its own, even when it came from the same run: relaunch creates a new physical context and D0b/R4 re-enrollment is unproved. N1 today needs continuous admitted play to the counter. Do not automate the long opening just to make a fixture appear selected.
- The owner accepts current near-3× numbers but one strict post-merge 173.0 floor invocation failed by 0.070. F0/P1 must settle the final explicit threshold **without** lowering 1×, quiet 3×, frame-skip, byte/ACK, backlog, or hold criteria, and run the frozen gate once. Do not tune FPS endlessly or claim 5×.
- C–E are planned, not implementation-authorized merely by this guide. A package with a missing owner choice or unexpected source behavior becomes HOLD with exact evidence; other disjoint packages continue.
