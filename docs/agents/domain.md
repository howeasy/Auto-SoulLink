# Domain documentation

Use the existing single-context [CONTEXT.md](../../CONTEXT.md) glossary before relevant code exploration. Read applicable docs/adr records if they exist. Missing optional ADR files are not a blocker; create a decision record only when an authorized domain-modeling task resolves a concrete decision.

Use the glossary's terms in code, tests, hypotheses and assignments. Identify a real terminology gap rather than inventing synonyms. Surface conflicts with an existing ADR and resolve them through the current owner/coordinator policy gates.

For Gen 1, also follow [the universal entry](../gen1_reference/README.md) and its current guide. The glossary describes domain meaning; the RC guide alone holds current work authority and evidence status. Other games and UI keep their own owners and domain decisions.
