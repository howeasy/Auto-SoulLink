# SLink orchestration hooks

The shared, read-only handler is `tools/agent_work_guard.py`. It injects the concise policy text and checkpoint pointer on session start, then a short reminder on user prompt submission. On Stop, it validates only the coordinator session named by a readable guide; an absent or malformed guide produces a visible scoped Stop failure. Child workers can finish and report to the coordinator without waiting for guide edits. Codex subagent hook input may carry the parent session ID, so only `Stop` is installed; `SubagentStop` is deliberately absent. Outside the configured SLink root it returns `{}`. It never edits a ledger or claims that mechanical checks prove useful work, actual sharing, or release readiness.

The coordinator should review the dry-run output of `tools/install_agent_work_hooks.py` with explicit `--scope-root`, `--guide`, `--register`, and `--policy` paths. Its defaults target user-level `~/.codex/hooks.json` and `~/.claude/settings.json`, so a session launched at the SLink root can see the same worktree guide. It installs the three event handlers, replacing an older handler only when its parsed script path and explicit hook marker match, while preserving unrelated handlers and settings; a repeat has no change. `--apply` backs up any changed existing JSON and writes the reviewed result. Do not install another copy at project level. The Python executable must have a shell-safe path without spaces; script/config paths are quoted. The installer rejects unsupported shell metacharacters in paths.

Codex hook discovery and the command/output formats are described in the [official hooks guide](https://learn.chatgpt.com/docs/hooks). Native command approval remains a separate `/hooks` UI trust step after installation. Do not edit the host trust database or bypass native hook trust. Confirm the installed version supports these events and check the host UI activation; a dry-run or JSON write alone is not an activated hook. Claude Code's equivalent lifecycle handlers are included as compatible JSON commands; verify that host's hook registration and test an actual event before claiming Claude activation. Other agent runtimes should receive the policy path in their dispatch unless their native hook API is independently verified.

The guide has exactly one `AGENT_CHECKPOINT_START`/`END` fenced JSON schema-1 block. Normal coordinator Stop requires a UTC timestamp within fifteen minutes (one minute future skew), readable register no more than one minute older than checkpoint, coordinator identity, source Git hex, live lane and next action. Worker entries need owner/state/exact relative files/next action/reuse decision, exclusive active files, a blocker reason when blocked, and receipt plus independent review references when done. Absolute, traversal and noncanonical claim paths are rejected. A deliberate owner pause uses `paused_by_owner: true`, `pause_reason`, `live_lane: null`, and no active workers; an old timestamp then does not restart a paused workflow. The handler blocks one invalid coordinator Stop with a specific repair reason; if `stop_hook_active` is true, it reports the failure visibly and allows the stop, avoiding a retry loop.
