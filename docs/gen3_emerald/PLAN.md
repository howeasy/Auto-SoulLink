## 2. Architecture decisions

1. **Two packs, not one**: `gen3_emerald` (title `emerald`, kinds `clean` sha1 `f3ae0881…` + `named` BPEE header fallback refused on site-byte mismatch) and `gen3_exp` (title per onboarded build, kind `clean` = exact build sha1; admission anchor = RHH magic + version + sites). Delete the stale `emerald` stub from `gen3_frlg/profile.json` (and the `firered_ap` stub stays where it is).
2. **Generators, not hand tables**: every pack field comes from a pinned `.sym/.map` (Emerald: pret build; expansion: our build) through the existing generators, extended by a title/config row — `tools/gen_gen3_profile.py`, `tools/pin_gen3_site.py` + `tools/gen_gen3_engine_signals.py`, `tools/gen_gen3_write_checkpoint.py`, `tools/gen_area_map.py`. The old-client stub is at most a cross-check input, never a source.
3. **Expansion struct offsets from the build itself**: compile a tiny `offsetof`/`sizeof` probe C file against the pinned expansion tree with the same compiler/flags (`-S`, read constants) → exact per-build `BattlePokemon`, `SaveBlock1/2`, `SpeciesInfo`, `MoveInfo`, `ItemInfo` layouts, honouring `FREE_*`/`P_*` config. No DWARF dependency, no hand math.
4. **One generic Lua/codec change for expansion**: profile-driven field masks + name length (`derived.MON_SPECIES_MASK`, `MON_ITEM_MASK`, `MON_MOVE_MASK`, `NICKNAME_LEN`, `NICKNAME_EXTRA_OFFS`) in `lua/gen3/reads.lua`/`boxes.lua` and `server/adapters/gen3_codec.py`; vanilla packs default to 0xFFFF/10 (no behaviour change, proven by the existing FR/LG/RR suites).
5. **Server**: Emerald stays on `Gen3Adapter` (`gen3_frlge.py`) with title-aware data (areas, badges exist, item overlay if E1 finds collisions); `foundation_for_rom_type("emerald") = "gen3_emerald"`. Expansion gets its own adapter `server/adapters/gen3_expansion.py` (game_id `gen3_exp`) that loads a **per-build data pack** (species names/types/abilities/evolution families, moves, items) extracted from the ROM via GF/RHH header pointers + probe offsets — game facts stay in the adapter/data, `pokemon_data.py` untouched.
6. **Vanilla trade = shared Gen 3 card** (FRLG PLAN §10 names it: shared prompt/input controller over `lua/hud.lua` + rollback-capable FSM); binds `gen3_frlg` and `gen3_emerald` in one design; its own gate.
7. **Branching**: `claude/gen3-emerald` off Gen 3 `5f050857` or later (frozen cut `a2985d5a` + the item-table fix); no commits on the Gen 3 branch. **Gen 3 coordinator grant (2026-09-25, cross-session):** no objection to `gen_gen3_profile.py`, `pin_gen3_site.py`, `gen_gen3_engine_signals.py`, `gen_gen3_write_checkpoint.py`, `build_pret_gba_syms.py --lock`, `gen3_codec.py`, `gen3_fixtures.py`, `lua/tests/gen3_title_syms.lua` — conditions: additive title rows only; FRLG **and RR** `--check` byte-identical; `gen3_codec.py` changes additive and **coordinated with the calc lane** (session "Damage calculator multi-game support" takes it byte-identical from `c0f6101b`); ruling 24 stands — the by-name refusal and the Manager unadmitted flag stay until the Emerald port is signed (EG4). Item-table defect accepted by Gen 3 as a P6 pre-release fix (after G4/G5, before G6); Gen 3 sends the sha, and this branch picks it up.

## 3a. Size: what's copied vs new

Baseline, measured on the Gen 3 branch (`4749a2c..b0f8df54`): FRLG+RR took **711 commits over 5 days**, about 95k inserted lines. | Server | small | state machine, species/moves/badges | ~300 lines: foundation, `rom_type`, statics/gifts, item overlay, sprite path, labels, area catalog |

About 5–8k new lines against ~95k, so **roughly 90% reuse by volume**. Time doesn't shrink as much, because the long pole is live gates (scripted play, duos, P+H physical runs), not code.
