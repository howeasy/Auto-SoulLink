# XG3 wild tables: compiled ROM readback (2026-09-29)

This is static compiled-ROM and SOURCE evidence for reference build `28877d73`, not a live wild-encounter receipt. The existing `expansion_encounters.json` source candidate and runtime adapters were not changed. Production routing and `live_verified=false` remain closed.

## Pin and geometry

- Integration starting HEAD `d7b7224a5c152ab4fb87f3b2981aa4dfa74f6a14`; pinned source `e8bd1cd7b03fc032ea37e3ecd38b379b5d01a1e7`; reference ROM SHA-1 `28877d733492299599f2b8fff50493109d72653c`; symbol SHA-256 `ac24a47c0137ab9b2233ccf37bf0cabe8b6eb08b715aa7e87f15787507a1f01e`. The verifier refuses a different or dirty source and relies on `expansion_inputs` for the ROM and symbol pins.
- `include/wild_encounter.h:18-48` defines `WildPokemon` as min/max level plus species enum (4 ROM bytes), `WildPokemonInfo` as encounter rate plus pointer (8 bytes with alignment), and `WildPokemonHeader` as map group/number plus `WildEncounterTypes[TIMES_OF_DAY_COUNT]`. `include/constants/rtc.h:97-105` has four time slots. Each type has five pointers, yielding the **pinned source/build** stride `4 + 4*5*4 = 84` bytes; this is not a general decoder geometry. `include/config/overworld.h:95-97` disables time-of-day encounters and selects the morning fallback. The other three time slots read as zero in every header.
- The fifth `WildEncounterTypes` member is `hiddenMonsInfo` (`include/wild_encounter.h:37`), at header `+20` for the morning slot. This source JSON declares only land/water/rock-smash/fishing fields; the pinned header generator iterates those fields and leaves the fifth C-initialized pointer null. All 124 fifth pointers were explicitly read as zero; their count and byte hash are in the generated receipt. A nonzero pointer fails structurally even when the SHA identity gate is bypassed for the mutation test.
- The `.sym` puts `gWildMonHeaders` at `08DEAA40`, size `0x2904 = 125*84`: 124 ordered active EMERALD entries and one `FF FF`/zero terminator. The verifier checks exact symbol sizes, ROM bounds, every expected map group/number, each pointer's exact compiled descriptor/array symbol, encounter-rate byte, each ordered level/species slot, and the terminator. A malformed descriptor pointer is refused before comparison can succeed.

## Result and limit

All 124 EMERALD headers match the pinned source in order. The ROM holds 95 land, 55 water, 6 rock-smash and 53 fishing descriptor tables. Nine distinct Altering Cave headers remain present and ordered; the area projection intentionally takes set 0, matching the existing source candidate's scope. The verifier independently aggregates decoded ROM slots by the source's method rates, first header per map and first method per area, and compares the result with `expansion_encounters.json["encounters"]`. The receipt records hashes of header order, decoded slots and the area projection instead of publishing ROM bytes.

The original readback test first failed RED because `tools.verify_gen3_exp_wild` was absent. Independent review `cx-ede958f2` then found that `raw[24:]` omitted the fifth pointer. A new changed-ROM `+20` pointer test failed RED (`DID NOT RAISE ValueError`); after the fix, all three focused tests passed (`3 passed in 1.03s`), including descriptor and hidden-pointer refusal. `python tools/verify_gen3_exp_wild.py --check` reported the receipt current. Tests skip only when local source or build artifacts are absent; present but wrong pins and malformed data fail. This proves the source candidate's set-0 table matches the pinned compiled ROM; it does not cover later Altering Cave selections, runtime overrides, scripted statics, randomized carts, or natural-play encounter delivery. Next PHYSICAL action is an isolated emulator receipt that samples method slots and variant selection against the observer, with independent save/reload where persistence matters.
