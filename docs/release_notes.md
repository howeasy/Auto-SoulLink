## What's new

Grouped by area, from the commit log between the merge-base `d2c30fb` and this branch tip.

**Client.** The Gen 1 client was rewritten from pret data rather than the pre-rewrite reverse-engineered evidence (`02283ce`): a composed runtime — `lua/gen1/entry.lua` wires reads, engine signals, guarded writes, boxes, ROM reads, the trade overlay and the native panel — sits under `lua/gen1/run.lua`'s BizHawk bootstrap. Generated profiles, engine-site bytes, wild/fishing tables, evolution families and dex mappings are pinned to pokered `405b6246372d7e5a2cb029cbb65219b13286b8c9` and pokeyellow `0a08515`; Archipelago is profile-generation-only in this release (`docs/gen1_requirements.md:3-24,46-51`). HUD rendering was moved into its own `pcall` after the protected tick so a tick error can no longer skip a frame's redraw, and a HUD error can no longer skip Gen 3-5 bookkeeping (`77d1e91`). Yellow-specific driver fixes (lab/parcel scripted play reaching first contact, `1a205c3`/`2492554`) landed alongside the shared Red/Blue path. The shared HUD module's `H.init` was fixed to derive `hud_y`/`font_size`/`char_width`/`prompt_h` from the screen size when a caller does not pass them explicitly (`63f7475`): the GBA-sized default (`hud_y=146`) sat below the Game Boy's 144-px screen, so the Gen 1 message bar (`lua/gen1/run.lua`, `duo_gen1_main.lua`) was never actually visible on-screen; GBA callers are unaffected since they already pass their own numbers. A package-boot receipt (`05bc4f1`) confirms the fix on the extracted release ZIP: a Manager-shaped launcher booting the new client from `SLINK_ROOT` shows the HUD bar inside the 144-px screen at frame 3000, no Lua errors. Notifications now word-wrap instead of truncating — the bar grows to three lines and the prompt to four (`7d64f76`) — and a burst of messages drains in a bounded window: identical text coalesces (refreshing the dwell instead of queueing again), the queue head is clamped to 90 frames while more are queued, and the newest four are kept, so the worst case on screen is 510 frames instead of unbounded. Expired banners actually leave the screen again: the per-render surface clear never ran in BizHawk, because the Lua API is exposed as NLua delegates whose Lua `type()` is `userdata`, so the `type(gui.clearGraphics) == "function"` guard (added so the module loads under lupa) was false on every real frame while every lupa test passed (`92ae732`; the text layer needs `gui.cleartext` alongside `gui.clearGraphics`, `ebc2639`). The fix makes the guards presence checks calling through `pcall`, and the pixel receipts under `tests/fixtures/gen1/receipts/hud_wrap/` show the three-line bar, the four-line prompt and a cleared screen after a five-message burst.

**Server.** `GameRulesAdapter.native_trade_ui()` (`eef6a1c`) replaced six `game_id == "gen1_rby"` branches in the shared trade FSM with a capability the Gen 1 adapter opts into for Red/Blue only — Yellow and every other game keep the ordinary server-driven trade menu, consistent with `supports_info_panel()`. Sync commands (`party_mon`, `box_mon`, `memorialize`) now stay in flight until acked or the reconciler's pass budget expires, closing a double-delivery bug where a drift reconciler could re-issue a command already on the wire (`d9225a1`); TCP sequence numbers are now scoped per connection and ignored before hello (`0629736`); the trade watchdog notifies both players when it abandons a confirming trade instead of freeing the slot silently (`580b3f8`); and the board's stat-stage chips read their labels from the adapter's `stat_stage_labels` capability, so Gen 1 renders DEF/SPC instead of Gen 3's SATK/SDEF (`56b2e2c`).

**Harness.** The duo E2E runner (`tools/e2e_duo.py`, game `gen1_new`) grew a dedicated Lua driver (`lua/tests/duo/duo_gen1_main.lua`, separate from the shared `duo_gb_main.lua` Gen 2 uses) and eighteen scenarios — `link_new`, `deadzone_new`, `linked_faint_bench_new`, `linked_faint_active_new`, `reconnect_new`, `ball_gate_new`, `trade_new`, `soft_reset_new`, `trade_decline_new`, `explode_new`, `pc_ops_new`, `changebox_new`, `whiteout_new`, `type_clause_new`, `species_clause_new`, `poison_new`, `rival_swap_new`, `admit_randomized_new` — pairing Red (player A) against Blue (player B). Battery-save fixtures for all three titles were rebuilt from scripted play rather than byte-staged (`tools/gen1_fixtures.py`, `tools/gen1_playthrough.py`). Individual scenario hardening landed throughout the sweep: the Explode branch's RNG-loss retry phrasing (`e6aa7a4`, `733cd59`), a walk-back path around incidental Route 1 grass battles (`f453238`), and the reconnect probe's kill-and-relaunch sequence (`944ec61`) — each red-first under the fail-closed runner and its live receipts. Later harness fixes: dead-zone rows no longer count as formed links in the poison oracle, and an oracle `RuntimeError` now ends a run as a FAIL summary line instead of a traceback (`9b87246`, H-2); `DuoRun.wait_for`'s dead-process rule was corrected so a finished half's own RESULT counts toward "both RESULT lines" instead of aborting the still-running half (`2395145` H-3, re-pinned by `f054b79` H-5 after it mis-fired on live poison/pc_ops/explode runs), and phase receipts plus a per-run wall-clock deadline were added to every wait; the poison hunt's encounter budget was rederived from `Forest.MAX_ENCOUNTERS` (60 × 3000 frames) instead of the flat 90000-frame `drive()` backstop, which had always tripped before a Weedle-less run could report `HUNT_EXHAUSTED` (`5b17723`). After the first full-runner sweep the oracle and driver were hardened against what its receipts exposed: H-6 fixed three oracle defects (`2c17161` — the explode move-menu markers now match the receipt's real format, the soft-reset baseline is snapshotted before the go-file, and a post-hoc wait can no longer quote its own PASS over an already-failed half); H-7 made a one-sided RNG-class FAIL retry instead of ending the run (`26d08f4`); and the soft-reset chord gate (`03db464`) holds A's body until the runner has taken its baseline, because the earlier `2c17161` "pre-reset" links baseline was in fact taken after the reset (vacuous) — `mon_stats` persist on the NEXT hello's save, so the second boot key only reached links.json on A's post-reset re-hello. H-8 relaxed the fixture qualifier to a stat band (`1484de0`): Gen 1 recalculates stats only on a level change, so stored stats are accepted in [recompute(stat exp 0), recompute(current stat exp)] instead of exact equality. The rival driver was re-seeded per battle — a stale `DisplayBattleMenu` baseline from the walk's incidental wild battle had answered "menu up" before `EnemySendOutFirstMon` ran (`8e345ac`) — and its replacement path was rebuilt as a flat frame-bounded nav → A → watch loop with a deduped `RIVAL_REPLACE` trace (`7370ff1`, `b8374a2`), proven live when the engine accepted the switch (`RIVAL_SWITCH slot=1` on the lane) and the fight played out (`rival_swap_new` PASS, `e803b91`). The rival oracle now compares the swap payload against B's party at command time, not at end of run (`785d11d`). The memorial oracle masks bit 7 of a boxed status byte: pokered's `RemoveFaintedPlayerMon` leaves `0x80` there for a red-bar faint and the cartridge itself writes it, so the client was right and the oracle was over-specified (`6e01e33`). "hunt ended whiteout" joined the retryable RNG class (`1dcb910`).

**Launchers and package.** Both production launchers now load the rewritten client (`ca17a26`): `lua/slink_gen1.lua` `dofile`s `lua/gen1/run.lua` directly, and the universal `lua/slink.lua` routes any GB/GBC cartridge through `Entry.detect_title` before it ever reaches the legacy `game_detect`/`_CLIENT_MAP` path. `tools/make_release.py` ships the rewritten client's full closure in the player ZIP — the ten `lua/gen1/*.lua` modules, `json_codec.lua`, `gen1_write_safety.lua`, and the five `data/games/gen1_rby/*.json` files `entry.lua` opens. The old-client cutover (P8-4) has since landed in two steps: the manifest stopped listing the legacy files first (`b3481dd`), then the legacy client's own source was deleted from the tree (`21ff0d7`) — the package no longer ships it because it no longer exists to ship.

**Legacy retirement.** The pre-rewrite Gen 1 gates, probes and console diagnostics were retired (`9aa7989`): 26 `lua/tests` scripts and `tools/gen1_ap_rom.py` deleted, `tests/live/test_gen1_gates.py` cut down to the companion-patch-only gates (patch, menu row, randomized panel), and the AP skip allowance dropped from both `tools/verify_gen1_release.py` and the `no_hardcoded_addresses` check. The two pre-rewrite client gates were dropped from the `live-gates` lane earlier in the sweep (`82ced2d`), and the adapter rewrite itself retired the old natdex tests (`02283ce`). The legacy client and its closure — `lua/clients/gen1_rby_client.lua`, `lua/games/gen1_rby.lua`, `gen1_rby_trainers.lua`, `lua/tests/gen1_gatelib.lua`, `lua/tests/gen1_playthrough.lua`, `data/games/gen1_rby/gen1_rby_{areas,locations}.lua`, `tools/gen_gen1_area_map.py` — was deleted outright (`21ff0d7`, Track B step 5 / P8-4b) after `b3481dd` (P8-4a) removed it from the launchers, the release manifest and `game_detect`; it no longer exists anywhere in this tree. The follow-on trim (`9969845`) cut the shared `memory_gb.lua` module down to what Gen 2 still calls, dropping every Gen-1-only helper the deleted client had used (1959 → 1512 lines), and `d2b107f` deduplicated the live-gate input drivers into a shared `lua/tests/gen1_inputs_common.lua`.

**Docs.** The ledger (`docs/gen1_requirements.md`), `docs/protocol.md`'s sync-command-lifetime section, `docs/gen1_engine_sites.md`, `docs/shared_runtime.md` and `docs/gen1_rebase_plan.md` were written or re-verified against the branch tip across roughly forty `docs(gen1*)` commits, tracking each requirement row's evidence as live receipts landed (e.g. `64a5bfb`).

**An explicit physical-evidence bar carries through all of the above.** A ledger requirement closes only with SOURCE plus PHYSICAL evidence: real cartridges in BizHawk, judged independently through engine hooks, Python decoding, game screens/save loading, server state or an independent control. MODEL tests alone never close a row; pre-rewrite evidence does not count (`docs/gen1_requirements.md:3-11,26-36`). The reusable mechanisms this rewrite produced — signal dispatch, armed write windows, hello/validation/queue handling, composition, JSON/HUD helpers, post-result oracles and the fail-closed runner — are porting material, not a completed cross-generation framework: Gen 1 layouts and policies remain Gen 1-specific, and a later consumer must supply its own bank/register model, site table, layouts and checkpoint predicate (`prep/PLAN_v3.9.md:874-887`).

## Final review (2026-09-20)

Two independent reviewers — the Codex “Review RBY” task and a Claude Fable agent with no prior context — reviewed the shipped Gen 1 closure. Their verdict on the `bbcd037` release candidate was **DO NOT SHIP**: four confirmed client defects could break a player's run; none of those four was a save-corruption finding. This entry records the fixes and committed evidence through `aa8a1df`; FIX-EVO-3 landed as `70b0cc8` (the byte-equal veto relaxes at battle end; pinned on R/B/Y).

1. **Slow nickname entry lost a successful catch and dead-zoned the area.** The `AddPartyMon` entry hook preceded `AskName`, but acquisition tracking expired after 600 frames. `64d9663` removed that acquisition deadline and settled the catch before considering `no_catch` at battle end. The live receipts committed in `9a41d78` show Red and Blue each holding the naming screen for 2400 frames, then sending exactly one `capture` and zero `no_catch`; both signal-to-capture gaps were 2653 frames (`tests/fixtures/gen1/receipts/slow_name_gate_red_2026-09-20.txt`, `slow_name_gate_blue_2026-09-20.txt`).
2. **An NPC trade from a non-last slot migrated the compacted neighbour's identity.** The hook ran before `DisplayPartyMenu`, and the client assumed replacement in place although the engine calls `RemovePokemon` then `AddPartyMon`. `64d9663` repinned `npc_trade` to the `RemovePokemon` call after selection and animation, and added `npc_trade_done` at `ClearScreen` after the recipient data and optional evolution are complete. SOURCE+MODEL checks cover the selected outgoing slot and appended recipient on R/B/Y. There is no live in-game NPC-trade receipt: none of the current fixtures is near one; the companion `trade_new` lane does not establish it.
3. **Level-up evolution was never hooked.** The after-battle path enters `EvolutionAfterBattle` past the `TryEvolvingMon` entry hook, so an ordinary first Caterpie evolution could orphan its link. `7616d9f` moved the hook to the post-write species-publication site shared by the evolution paths. Cross-review then confirmed two further defects — stale-slot acquisition after retiring the old key, and DV:OT-prefix ambiguity with a boxed mon. Their follow-up, FIX-EVO-2 (`da2cf11`), adds a freshness witness on the slot the engine is about to write and takes the evolution's old key from the party as read before the signal; both are pinned on R/B/Y. Cross-review of `da2cf11` then confirmed that a byte-identical reacquisition can remain permanently suppressed by the freshness veto, even after battle completion. **FIX-EVO-3 landed as 70b0cc8 (the byte-equal veto relaxes at battle end; pinned on R/B/Y).** The missing-pre-signal-read case remains a recorded initialization limit below.
4. **A full-party whiteout rebuild could deadlock when retrieval preceded memorials.** `party_mon` failed as “party full” before the queued memorials freed a slot; the server treated that failure as final, leaving the last memorial waiting for a replacement that would never arrive. `7616d9f` adds bounded tail requeue on “party full” without prematurely sending `sync_retrieve_failed`. This is conditional on command order: ordinary individual faint events can already have queued the memorials first.

The evolution-gate corrections in `d0b13dc` are backed by the **PASS receipts committed in `aa8a1df`** (`tests/fixtures/gen1/receipts/evolution_gate_red_2026-09-20.txt`, `evolution_gate_blue_2026-09-20.txt`). Red records catch frame **14712**, level-up **42480**, evolve signal **43711** and `key_change` **43712**, `7292:4190:70` -> `7292:4190:71` (**KAKUNA**); Blue records **9267 / 22957 / 24188 / 24189**, `BD18:AFB9:70` -> `BD18:AFB9:71`. Both receipts have `after_battle_hits=1` and `try_hits=0`: `EvolutionAfterBattle` ran and `TryEvolvingMon` never entered. The gate stages the caught mon's experience to one below level 7 before the leveling battle — an instrument shortcut logged as `EXP_STAGED`, with the key asserted unchanged. The cancel variant was dropped in `d0b13dc` because its B-button cadence never landed in `Evolution_CheckForCancel`'s poll; these PASS receipts do not qualify cancellation.

The review also found the universal launcher's opt-in SGB route missing; `be29c9d` adds `SGB` alongside `GB` and `GBC`. SGB is off in stock EmuHawk configuration; the routing fix is not a live SGB qualification.

Outside those findings, the source review confirmed the SRAM write layout/checksum calculations against pinned pret on Red, Blue and Yellow, with **167/167 profile RAM symbols per title** matching the title symbols. No new defect was established in the inspected HUD, package closure or reconnect identity handling; their existing receipts retain their stated scope. This does not remove the recorded save-tear window, establish crash safety or supply missing Yellow duo evidence.

Limits recorded earlier, kept in full:

- **Box writes touch the game's own SRAM structures.** The initialised-boxes flag + main checksum are written as two bank-1 bytes (`780d6c1`); a process death between them rejects the save on boot (two-write window). Recomputing the checksum would also re-seal a damaged-but-named save (unreachable mid-run: the save loaded at boot). A crash between the bank-1 write and the WRAM flag write self-heals on the next hello (memorialize re-queued). OMP review REVIEW-BOXES-1.
- **Force-faint demotion is silent.** When the queued in-battle write misses its `MainInBattleLoop` head (the mon was switched out or already KO'd before the next head), `lua/gen1/client.lua:754-756` moves it to the checkpoint queue and `:411-421` drops it if the key has left the party, logging one line and sending no NACK (the protocol has none). Observed live 2026-09-17 in a `linked_faint_active_new` run where the wild KO'd the 5/15-HP linked mon in the same turn; the scenario now cancels the move menu so the write lands before any enemy move.
