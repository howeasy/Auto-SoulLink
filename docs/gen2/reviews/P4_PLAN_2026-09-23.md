## 1. Ticket 14: mailbox placement (D1)

### 1.1 What the mailbox must hold

The Gen 1 ABI-3 uses +0..13: beacon, ABI, 16-bit counter, SFX request, caps, panel state, page, pages
and SFX hold/stamp (`patch/gen1/src/slink.asm:38-66`). A 16-byte trade lease in the tail (D2)
brings the total to **30 B**, the size Gen 1 had at `$DEE2`. The mailbox must be always mapped
(WRAM0 or HRAM, never WRAMX or SRAM without a bank protocol). It must survive warp, battle, menu
and link, must not be saved, and must be cleared on power-on/reset.

### 1.3 Lifecycle contract (A)

| Event | Effect on the span | Source |
|---|---|---|
| Power-on / soft reset | zeroed: `Init` clears all WRAM0 (`Reset` jumps to `Init`) | C `home/init.asm:66-74`, `:1-18`; G `home/init.asm:59-68` (WRAM0+WRAMX) |
| New Game | **not** cleared: `_ResetWRAM` fills `wShadowOAM..wOptions` (C `$C400..$CFCB`, G `$C300..$D198`), `STARTOF(WRAMX)..wGameData` and `wGameData..End` | C `engine/menus/intro_menu.asm:101-116`; G `:28-37` |
| Save / Continue | not copied: `_SaveGameData` copies `wOptions..wOptionsEnd`, player/party/box blocks, all outside the span | C `engine/menus/save.asm:491,554,685,703,724` |
| Link session | not touched: link buffers sit in the Overworld Map union / WRAMX | `.map` |
| Stack | C stack `$C000-$C0FF` grows toward `$BFFF`; G stack `$DF03-$DFFF` (WRAMX 1). Neither can reach the span | `.map`, `pokegold.sym:43091` |

Contract rules:

- **Ownership:** only SLink code writes the span, plus the Lua host through the armed write gate at
  the ABI's host-owned offsets (SFX +7, panel state +9, pages +11, lease bytes).
- **Beacon, ABI and caps:** rewritten by the patch on every service call. This matters because New
  Game doesn't clear the span: the service must treat panel state as transient, and the host clears
  its own requests on reconnect.
- **Frame counter +5..6:** kept by the main-thread service from `hVBlankCounter` deltas (C
  `home/vblank.asm:65`). That means **no VBlank ISR edit** (see P4.1c's falsifier).
- **Allocation:** the overlay pins `SECTION "SLink Mailbox", WRAM0[$CFD8]` (C) / `[$C1D9]` (G/S). The
  linker then refuses any overlapping section in this build and every future one. That is the
  allocation half of "a separately reviewed patch that establishes them" (PLAN §11).

W1-W5 are the proof. W6 is the detector, and PLAN §11 says a memory watch alone never proves no
writer exists.

**Named risk:** source review can't exclude a *computed-pointer* write that runs past its buffer
(a glitch, or an uncounted overrun in a routine W4 misses because its length comes from data). The
spans border the time-since counters (C) and PC-cursor bytes (G), which are single-byte writers.
Residual risk is low. W6 is the tripwire, and the patch rewrites beacon/ABI/caps on every service
call, so a corrupted header self-heals and a corrupted request byte costs one lost cue, not state.

### 2.3 Held items and mail (D3, O-14, T-3)

Validation happens on the host before OFFER and again in the patch before APPLY. Rule: the item id
exists in the **receiver's** `data/games/gen2_<title>/items.json` as a holdable item and is not a
mail item (`ItemIsMail`). Otherwise the offer is refused with a reason code and neither save
changes. Options for mail: **refuse (rec.)** / strip mail (item loss, silent) / carry mail (the
recorded limit says no). Trade evolution with a held item (e.g. King's Rock) is the game's own
`EvolvePokemon`, and the DONE record must report the post-evolution species/item.

## 3. Ticket 16: sound (D5)

Facts (C, same in G): Gen 2 SFX ids are one global table, so there is **no per-bank resolution**
like Gen 1's. `PlaySFX` takes `de`, gates on `CheckSFX` (ch5-8 on) plus the `wCurSFX` priority, and
has no DI (`home/audio.asm:180-218, 504-522`). The VBlank reentrancy counterexample stands (PLAN
§5.12), so service stays on the main thread. `DelayFrame` is reached by menus (`engine/menus/menu.asm:37`,
`home/joypad.asm:266,294,420`), by text (`home/text.asm:497,610,896,973` via `DelayFrames`) and by the
overworld unless `wOverworldDelay` is used up (`events.asm:182-186`). `Joypad` is a `reti` stub.
Candidate codes, verified at both pins (`constants/sfx_constants.asm`): success `SFX_ITEM $01`
(or `SFX_LEVEL_UP $90`), failure `SFX_WRONG $19`, boo `SFX_BUMP $24`, notify `SFX_READ_TEXT_2 $08`.
Final picks go to the owner's ears at G4.

| Opt | Sites | Verdict |
|---|---|---|
| **A (rec.)** | `DelayFrame` bridge only (ROM0 padding → farcall `SlinkService`), with a hold while `CheckSFX` is busy or a music fade runs, and a 240-frame stamped hold against the mailbox counter (Gen 1 semantics) | smallest; each of the five contexts (movement, idle START menu, text, battle, transitions) plus reset gets its own deadline falsifier |
| B | `DelayFrame` + `GetJoypad`/`JoyTextDelay` from day one (the Gen 1 two-site shape) | Gen 1 needed two sites because its menus never reach DelayFrame, and Gen 2's do. Keep it as fallback card P4.2d, run only on a red context |
| C | VBlank signals, main thread drains | same as A plus an ISR edit; no benefit |
