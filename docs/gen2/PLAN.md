## 1. Context: why

Gen 1 is the project's code contract (`docs/gen1_requirements.md:3-11`; `GEN1_STANDARD_DIGEST.md`):
composition root over injected io/net/hud, engine events from byte-verified execution sites, one
armed write gate behind a source-established checkpoint, profile-driven reads with an independent
Python codec, fail-closed release runner, duo verdicts from saved-state oracles. pureRGB proved a
second foundation binds it; Gen 3 is being ported onto it (`SWEEP docs/gen1_reference/GEN3_BINDING_PLAN.md`).

Gen 2 today is the smallest client in the repo (`lua/clients/gen2_crystal_client.lua` 1484 lines,
`lua/memory_gb.lua` 1499, `lua/games/gen2_crystal.lua` 612, `server/adapters/gen2_crystal.py` 416)
and the structural opposite of Gen 1: polling and RAM diffing instead of execution sites, direct
writes without an armed gate, a staged fixture (`lua/tests/gen2_playthrough.lua:283-298` writes a
Totodile into slot 0 instead of playing Elm's lab), three duo scenarios judged by the client's own
RESULT line, no Python codec twin, and an Archipelago profile the address verifier never reaches
(`research/omp_address_audit.md`, finding 1). Its addresses agree with pret where the verifier can
see them (102/102, `research/omp_address_audit.md`), which proves the profile agrees with the
symbol JSON, not that the client is right: the Codex site audit found a boxed catch that never
emits `capture`, a withdrawal debounce that cannot complete, and the egg marker read from the wrong
array (`research/codex_engine_site_audit.md`, findings 1-3). Hence rewrite, not strangler
(owner O-3): nothing in the old code is evidence, so keeping it running buys no safety.
