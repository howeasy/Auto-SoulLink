## Source cut and classification

Classification is deliberately narrow. **SOURCE-BACKED** means a named byte/record has a matching value in `data/pret_syms.json` and a corresponding declaration at the requested pret pin. It does **not** mean a polling transition is complete or a write is safe. **COMMENT-ONLY** means an asserted symbol/semantic connection exists only in prose. **UNBACKED** marks literal thresholds, inferred event identities, or admission assumptions without an execution witness. **MISSING** means the specific event has no dedicated detection in these inputs; incidental party/tick changes are noted separately. Composite rows classify the byte and the event inference separately rather than promote the whole inference because its address is correct.

First falsifiers: a full-party catch should emit `capture`; a stable known-key withdrawal should reach the three-sample debounce; a `GiveEgg` result should set `is_egg`. Static inspection already contradicts each expected path below. These are proposed replay assertions, not tests executed in this documentation-only task.

## Findings requiring coordinator attention

1. **High: full-party catch has no publication path.** L `:680-696` seeds keys only, while `:964-969` can still mark the encounter failed. C `engine/items/item_effects.asm:609-632` is a distinct successful capture branch. This is a code-path finding, not a claim of a reproduced live failure.
2. **High: withdrawal debounce cannot complete on ordinary stable reappearance.** L `:936-946` only increments when absent from previous snapshot, but `:977` updates that snapshot immediately. Deposit explicitly carries an existing debounce forward (`:896`); withdrawal does not. This can be falsified with a tiny sequence replay before any future fix.
3. **High: egg marker is read from the wrong array.** The record contains underlying species; the parallel species list contains EGG (C/G `engine/pokemon/move_mon.asm:1175-1188`). M `:353-355` uses record species. A related COMMENT-ONLY premise is wrong: A `:46-47` and L `:661-662` describe Mr. Pokémon's Mystery Egg as a Pokémon gift; C `maps/MrPokemonsHouse.asm:31` is `giveitem MYSTERY_EGG`, a key item, not `giveegg`.
4. **High: safe, reset, and acquisition identity are heuristics.** Correct addresses do not validate historical prose about menus or make DV/OT/species a unique identity. L `:785-813` can even classify an all-filtered party as whiteout. These require bounded sequence falsifiers and execution witnesses.
5. **Medium: several comments overstate or contradict code.** L `:679` says box scan disabled despite calls; L `:669-671` names `wInBattle` and -1 although the profile reads `wBattleMode`; P `:243-246` repeats trainer-only Gold/Silver differences despite G `data/wild/johto_grass.asm:341-364`. Address equality is not a release receipt.

Confidence: high for direct control flow, source declarations, and the 60-value equality check; no confidence claim about unrun timing or emulator coverage. No inference here treats SLink's own Lua/Python as authority for engine behavior.

## Comparison with the Gen 1 site-table standard

`docs/gen1_engine_sites.md:198-240` section 3 separates event, routine/source line, per-title bank/address, bytes/register/WRAM observation phase, status and traps. Its faint/capture rows distinguish successful commit sites from entry/attempt sites. The concrete artifact `data/games/gen1_rby/engine_signals.json:27-69` contains clean SHA-1, site symbol, bank, address, ROM offset, `expected_hex`, and optional `capture_offset` (e.g. bag receipt). The schema/verification explanation at `docs/gen1_engine_sites.md:57-110` requires source and symbol provenance, byte anchors, bank/PC predicates and before-instruction observation semantics.

The existing Gen 2 inputs have no equivalent generated site table, no `event.on_bus_exec` calls, no `expected_hex` checks, and no cartridge hash in hello. The 60 address matches qualify reads under the requested definition only. Candidate routines below must still gain exact successful instruction boundaries, caller/context predicates, canonical bytes, register/data capture definitions, duplicate suppression, and negative cases. Routine existence alone is not a qualified hook.
