# Gen 1 (R/B/Y, US) engine site table for the bus-exec client rewrite

Every game event the rewritten Lua client reports is detected from the engine's own
execution: a BizHawk `event.on_bus_exec` hook at a pret routine address, with the
routine's bytes verified at load. No WRAM-diff heuristics. This file is the site table
that rewrite implements.

Legend used in every row:

- **RC** = already pinned, byte-verified and (where stated) live-proven in the RC worktree
  `gen1-rby-code-sweep-8d06e2`; the artefact is cited.
- **NEW LOOKUP** = derived here from the pinned pret checkouts and `.sym` files and
  byte-checked against the three clean US ROMs found in the RC worktree root. Nothing marked
  NEW LOOKUP has been exercised on an emulator.
- Addresses are `bank:addr (flat)`. `flat = bank*0x4000 + (addr - 0x4000)` for switchable
  banks, `flat = addr` for bank 0 (`tools/gen_gen1_acquisition_sources.py:59-60`, RC).
  `data/pret_rom_syms.json` in this worktree stores `(bank << 16) | addr`, NOT flat
  (`tools/build_pret_syms.py:329-352`, `tools/verify_gen1_rom_layout.py:12-15`).
- Red and Blue share every code address and every WRAM address below (`pokeblue.sym`
  differs from `pokered.sym` only in data banks). "R/B" therefore means both; Yellow is
  listed separately because most WRAM symbols are one byte lower and the battle-init code
  moved to bank $3D.
- `symline N` = line in the `.sym` file the address was read from; `file:line` = the pinned
  pret source. Line numbers are for the pinned commits below.

## 1. The RC engine-signal pattern the rewrite copies

### 1.1 `data/games/gen1_rby/engine_signals.json` schema (`rby-engine-signal-sites-v1`)

Generated by `(R)/tools/gen_gen1_engine_signals.py` (mirrored to `gen1_engine_signal_data.lua`
by `lua()` at :83-90, checked stale by `--check` :100-101):

```
{ "schema": "rby-engine-signal-sites-v1",
  "sha256": <sha256 of json.dumps(result, sort_keys, separators=(',',':')) before this key>,   # :79
  "titles": { "red"|"blue"|"yellow": {
      "source_commit":  <pret commit from pret_sources.lock.json>,                            # :75
      "symbols_sha256": <sha256 of the .sym file bytes>,                                       # :76
      "clean_sha1":     <clean ROM sha1 from the lock>,                                        # :77
      "starter_map":    40,
      "addresses":      { "<wSymbol>": <cpu addr> ... },   # :70-73, 78  (17 names incl. hLoadedROMBank)
      "sites": { "<kind>": {
          "symbol":         "<pret label, may be Label.sub>",
          "bank":           <rom bank>,
          "address":        <cpu addr of symbol (+ sub-offset)>,
          "rom_offset":     <flat>,                                                            # address() :59-60
          "expected_hex":   <clean-ROM bytes at rom_offset, default 8, call sites 3>,          # site() :31-35
          "capture_offset": <optional: bytes past address where the hook is registered>        # :60, :69
      } } } } }
```

How each site is pinned in the generator: `site(name, offset, length)` (:31-35) reads the
`.sym`, adds `offset`, computes `rom_offset`, slices the clean ROM. Then a source-text assert
proves the label still means what the observer assumes (`:37`, `:42-43`, `:56`, `:65`) and a
byte assert proves the slice has the expected shape (`:40`, `:59`, `:68`). `capture_offset`
exists because the hook must fire at a specific instruction *after* the label: `bag_received`
= `.done+8` (the `ret`, :57-60), `save_witness` = `SaveMenu.save+3` (the instruction after
`call SaveGameData`, :61-69).

The other RC site files (`wild_encounter_sites.json`, `capture_sites.json`, `evolution_sites.json`,
`continue_sites.json`, `bootstrap_sites.json`, `static_sites.json`, `grant_sites.json`,
`npc_exchange_sites.json`, `identity_sites.json`) use the same site shape plus extra anchors
(`prelude`, `call`, `reset`, `return`) that pin neighbouring bytes without hooking them.

### 1.2 How `lua/gen1_engine_signals.lua` verifies and registers (line refs)

- `:9-12 hex()` reads bytes from any domain; `:20-23 check()` asserts `gameinfo.getromhash()`
  equals the admitted `final_sha1` and the owned context is unchanged.
- `:52-56` load-time anchor check: for every site `hex(site.rom_offset, n, "ROM") == expected_hex`
  (flat ROM domain, bank-independent) else `"engine observation ROM anchor differs"`.
- `:57-87` registration: `event.on_bus_exec(cb, site.address + (capture_offset or 0),
  "SLink-engine-"..kind, "System Bus")`; `:86` asserts the id.
- Callback (`:58-84`): `:60` bank gate `memory.read_u8(hLoadedROMBank) ~= site.bank -> return`
  (a bus-exec matches the 16-bit CPU address in whichever bank is mapped); `:61-65` per-kind
  register predicates via `emu.getregister("H"/"L"/"F")`; `:66-69` re-`check()`, buffer bound,
  `emu.getregister("PC") == address+capture_offset`, and `hex(site.address, n)` from the
  System Bus == `expected_hex` (bytes of the mapped bank at the CPU address); `:70-73` capture
  `emu.framecount()` and assert it is unchanged after `point()`; `:78-82` `client.saveram()`
  after a save witness.
- `MAX_PENDING=32` bounded buffer, `peek/drain/flush` only under a held frame boundary
  (`:90-135`). The rewrite keeps the verification half; the held-frame publication half is the
  RC execution model and is not required by a free-running client.
- The same bank gate + PC + bytes pattern is in `gen1_wild_encounter_observer.lua:32-43` and
  `gen1_write_safety.lua:27-44` (ROM anchors re-verified on every check, never cached, `:36-37`).

**Bank-0 rule (new for the rewrite).** Every RC site lives in a switchable bank, so `:60` is
always right there. Several sites below are `home` routines (bank 0, addr < $4000). For those
the `hLoadedROMBank == bank` gate must be skipped (any mapped bank is legal); PC and byte checks
still apply, and `rom_offset == address`.

**Patched-cartridge rule.** `check()` compares against the *admitted* cartridge hash, which for
SLink is the companion/UPR-patched ROM, while `expected_hex` comes from the *clean* ROM. This
only works because every RC site sits in bytes the patch and UPR never touch
(`RomChangeAudit`, cf. `grant_sites.json … "policy": "pinned: gen1_upr_scan never claims these
bytes"`). Section 3.n names the one place this bites (`DrawStartMenu` is patched).

### 1.3 Hook-frame convention and bus-exec semantics (BizHawk 2.11.1, Gambatte)

- `emu.framecount()` observed inside an `on_bus_exec` callback equals the frame armed for:
  `HOOK_FRAME_OFFSET = 0`, measured on red, blue and yellow under both `emu.frameadvance` and
  `platform_bounded_execution.step_one` (`BATTLE_FORCE_FAINT_WINDOW.md:352-355, 376-377`).
  `gen1_engine_signals.lua:70-73` additionally asserts the frame did not change while the
  point was read.
- Bus-exec callbacks fire for call targets, jump targets and linearly-executed addresses alike,
  in bank 0 and in switchable banks (`BATTLE_FORCE_FAINT_WINDOW.md:411-415`, probes
  `lua/tests/probe_battle_exec.lua`, `probe_exec_callbacks.lua`). Hence the bank gate above,
  and hence a hook placed *inside* a routine (e.g. `SaveMenu.save+3`) is as reliable as one at
  its entry.
- The hook fires before the instruction at that PC executes; registers/WRAM are the state
  *entering* that instruction (all "WRAM at hook" columns below are written for that instant).
- Under `step_one`, `joypad.set` is sticky; under `emu.frameadvance` it auto-releases
  (`BATTLE_FORCE_FAINT_WINDOW.md:405-410`). Fixture drivers set all eight buttons every frame.
- Frame-boundary PC for a *halted* CPU is the IRQ vector `$0040`; for a busy-looping CPU it is
  unknown (`BATTLE_FORCE_FAINT_WINDOW.md:96-105`), which is why the overworld checkpoint pins
  `[SP]` and the battle menu cannot be pinned.

## 4. Traps that cut across groups

1. **Bank gate vs bank 0.** RC's `hLoadedROMBank == site.bank` (`gen1_engine_signals.lua:60`) is
   mandatory for every `$4000-$7FFF` site and must be skipped for every `home` site
   (`AddPartyMon`, `LoadMapHeader`, `EnterMap`, `HandleBlackOut`, `HandleFlyWarpOrDungeonWarp`,
   `RedisplayStartMenu+$13`, `HandlePartyMenuInput`, `SoftReset`/`Init`, `.allPokemonFainted`).
2. **Yellow bank moves.** Battle init, `_GivePokemon`, `AddItemToInventory_`,
   `RemoveItemFromInventory_` are bank `$3D` in Yellow (bank `$0F`/`$13`/`$03` in R/B);
   `ResetStatusAndHalveMoneyOnBlackout` is `$3C` (R/B `$01`); `InGameTrade_CheckForTradeEvo` is
   `$1C` (R/B `$05`); `EvolveMon` `$17` (R/B `$1E`). Never assume a bank carries over.
3. **Hooks fire before the instruction.** A hook at `ld [wIsInBattle],a` sees the old value;
   hook the next instruction (or the routine that follows) to read the new one.
4. **Shared routines need a caller pin.** `AddPartyMon`, `SendNewMonToBox`, `HealParty`,
   `SavePartyAndDexData`, `MoveMon`, `RemovePokemon`, `TryEvolvingMon`, `TryLoadSaveFile`,
   `LoadMapHeader` all have multiple callers; the table names the unique site to hook instead,
   or the `[SP]`/WRAM discriminator.
5. **Latches.** `no_catch` (c) and "capture happened this battle" (a) require per-battle
   latches cleared at `InitWildBattle+5` and at `Init+0`; blackout cause (d) requires reading
   `wIsInBattle`/`wOutOfBattleBlackout` at `HandleBlackOut+0` before `Reset…` zeroes them.
6. **Insert-at-0 box semantics** (b) and **first-`ChangeBox` SRAM wipe** (g).
7. **Patched cartridges.** `expected_hex` is clean-ROM; the admitted hash is the patched ROM.
   Every hook must sit outside the companion-patch manifest spans and outside UPR domains
   (`tools/verify_gen1_rom_layout.py` checks the manifest spans; add a check that no hook site
   intersects them).
