# Gen 3 overworld write checkpoint — SOURCE writer inventory and predicate (P2 card C2-7)

The Gen 1 checkpoint (`lua/gen1_write_safety.lua`, `data/games/gen1_rby/write_checkpoint.json`)
admits a host write only while the main thread is parked in `DelayFrame`'s `halt` reached from
`OverworldLoop`. Gen 3 has no such single park, so PLAN §5.3 defines the predicate the other way
round: enumerate every code path that can mutate the state we write, then admit a write only when
**no inventory member can be in progress**.

This document is the inventory and the derivation. The machine-readable form is
`data/games/gen3_frlg/write_checkpoint.json` and `data/games/gen3_rr/write_checkpoint.json`,
regenerated by `tools/gen_gen3_write_checkpoint.py` and asserted by
`tests/unit/test_gen3_write_checkpoint.py`.

Nothing here was measured on an emulator except the CPU census, which is cited where it is used.

## 1. How Radical Red facts are earned

RR ships no symbols. Every FRLG fact that reaches `data/games/gen3_rr/write_checkpoint.json` is
re-derived from the RR binaries first, by one of two checks the generator performs:

* **code symbol** — the whole FireRed function body is byte-identical at the same address in
  *both* RR ROMs (clean and companion). A hit means CFRU neither moved nor rewrote that function.
* **data symbol** — the literal-pool word(s) that hold the symbol's address inside a named
  FireRed *witness* function still hold the same address at the same offsets in both RR ROMs.
  This is the stronger tool here, because it survives a patched instruction elsewhere in the
  witness (the SLink companion writes its frame hook straight into `CallCallbacks`, yet the
  `gMain` pool word four instructions later is untouched).

Anything that fails is **never emitted into the JSON**; it is listed in §5 as UNVERIFIED. Missing
fact ⇒ missing predicate ⇒ fail-closed, exactly as Gen 1 treats an unreadable checkpoint byte.

### 2.1 The companion mailbox arena (RR only)

The SLink companion's own handlers write an EWRAM arena that is not part of any pret inventory.
Its addresses live in `data/games/gen3_rr/profile.json` `native`: base `0x0203F800` (`SIG`
`0x4B4E4C53`), scratch/window block from `0x0203F740`, text/menu/ghost/info buffers up to
`~0x0203FD50`. The P1 write probe caught natural companion traffic at `0x0203F800`
(`hooks_rr_companion_2026-09-21.txt`, `HIT write+0 … val=0x4B4E4C53 r15=0x08378F7E`). The
checkpoint does not police this arena — native op staging is the `native.lua` queue's own
invariant (PLAN §5.3 "no mailbox transaction in flight") and is owned by P5, not by this card.

### 3.1 Resolving the census set

The P1 census sampled 1800 frame-ends of RR standing idle in the overworld and saw exactly one
task-function set, `{0806E811, 0806E83D, 08079E0D}` (Thumb pointers). Stripping the Thumb bit and
looking the addresses up in `pokefirered.sym`:

| census value | address | FireRed symbol | proof |
|---|---|---|---|
| `0806E811` | `0x0806E810` | `Task_RunPerStepCallback` (`src/field_tasks.c:66`) | exact `.sym` hit; 44-byte body byte-identical in RR clean **and** companion |
| `0806E83D` | `0x0806E83C` | `Task_RunTimeBasedEvents` (`src/field_tasks.c:76`) | exact `.sym` hit; 64-byte body byte-identical in both RR ROMs |
| `08079E0D` | `0x08079E0C` | `Task_WeatherMain` (`src/field_weather.c:219`) | exact `.sym` hit; 180-byte body byte-identical in both RR ROMs |

All three are **VERIFIED**, not assumed: the byte comparison is what turns a FireRed symbol name
into a Radical Red fact. (LeafGreen relocates only the third: `Task_WeatherMain` is at
`0x08079DE0` in `pokeleafgreen.sym`, with the same body bytes. The generator always reads each
title's own `.sym`, so no address is shared across titles by accident.)

### 3.2 Deriving the same set from source

Independently of the census, these are exactly the tasks FRLG creates for an idle field map:

* `SetUpFieldTasks()` (`src/field_tasks.c:84-94`) creates `Task_RunPerStepCallback` (priority 80,
  `tCallbackId = STEP_CB_DUMMY`) and `Task_RunTimeBasedEvents` (priority 80), each guarded by
  `FuncIsActiveTask` so there is at most one of each.
* `StartWeather()` (`src/field_weather.c:146,170`) creates `Task_WeatherInit`, which rewrites its
  own `gTasks[].func` to `Task_WeatherMain` (`src/field_weather.c:215`).
* Both are reached from the Overworld resume paths `src/overworld.c:2118-2121` and `:2444-2446`.

So `allowed_overworld_tasks` = {`Task_RunPerStepCallback`, `Task_RunTimeBasedEvents`,
`Task_WeatherMain`}, per title, at that title's `.sym` address with the Thumb bit stripped.

`Task_WeatherInit` is deliberately **excluded**. It is the transient that becomes
`Task_WeatherMain`; a frame in which the weather initialiser is still running is not an idle
frame, and the allow-list is fail-closed by construction — an unknown task means "not safe",
never "probably fine".

`gTasks` is 16 entries of 0x28 bytes (`include/task.h`, `NUM_TASKS 16`,
`struct Task { TaskFunc func; bool8 isActive; u8 prev, next, priority; s16 data[16]; }`), and the
`.sym` size `0x280` confirms it. The checkpoint walks all 16 slots and requires every slot with
`isActive != 0` to have a `func` in the allow-list.

party or the save while `callback2 == CB2_Overworld`; each of them is caught by

the set rather than just the callback pair.

### 4.3 The parked-PC clause

PLAN §5.3 left this to the census. The clause is **per title**: one R15 range plus CPSR mode and
T bit, emitted by the generator; `lua/gen3/safety.lua` holds no game fact.

**FRLG** park in ROM. `AgbMain` ends every frame by calling `WaitForVBlank`
(`src/main.c:216`), a busy-wait on `gMain.intrCheck` (`src/main.c:462-468`). The range is that
symbol's whole body from each title's own `.sym` (`08000890 l 00000030 WaitForVBlank`, the same
address in `pokefirered.sym` and `pokeleafgreen.sym`): **mode `0x1F`, `T == 1`, R15 ∈
`[0x08000890,0x080008BF]`**. FR census (`census_fr_overworld_2026-09-21.txt`): 1707/1800 frame
ends at R15 `0x080008AC..0x080008B4`, mode 31, T=1; `observed_pc` keeps the modal `0x080008AC`.
The other 93 (~5%) landed on the BIOS IRQ vector (R15 `0x0000001C`, mode `0x12` IRQ, T=0). Those
are **refused on purpose**: an IRQ handler is mid-flight, and the next parked frame admits, so
liveness holds. LG has no census; its block has no `observed_pc`/`census`, only the symbol.

**Radical Red** (CFRU) parks in the BIOS instead. Over 1800 frame-ends of RR overworld-idle, R15
was `0x000001C4` on **every** frame, CPSR mode `0x1F` (System) with `T = 0`
(`census_rr_overworld_2026-09-21.txt`), inside the GBA BIOS `IntrWait` path. The clause is
**mode `0x1F`, `T == 0`, R15 in the BIOS range `[0x0000,0x3FFF]`**, with the exact observed
value kept in the JSON as `observed_pc` for reference only — the predicate tests the range, not
the single value, because one savestate on one build is not a proof that no other BIOS address
can be the parked PC.

Not sampled in that run: menu, battle and save buckets (no input script). PLAN §6 P3's scripted
play covers them, and until then this clause is a *necessary* condition only.

### 4.4 SaveBlock pointer snapshot and revalidation

Vanilla FRLG re-points all three (`gSaveBlock1Ptr`, `gSaveBlock2Ptr`, `gPokemonStoragePtr`) by
one random offset (`src/load_save.c:69-83` `SetSaveBlocksPointers`, called from
`MoveSaveBlocks_ResetHeap` `:110`) on every battle start (`src/battle_main.c:614`) and map load
(`src/overworld.c:1337`); `UpdateSaveAddresses` (`src/save.c:630`) re-reads them into the sector
table on every save.

RR keeps the same three pointer variables, and pins the relocation offset to 0: `0x0804C062` is
`movs r1,#0` twice where vanilla has `movs r1,#0x7C; ands r1,r0` (`:75`; both RR artifacts are
read by `test_gen3_safety_unreached.py:162-167`). `tools/gen_gen3_write_checkpoint.py` takes the
setter's address from `pokefirered.sym`, signature-checks the body, and reads the three addresses
out of the function's own literal pool (ROM file `0x4C08C..0x4C0A3`) — nothing about the pointers
comes from the old client's table:

| title | gSaveBlock1Ptr | gSaveBlock2Ptr | gPokemonStoragePtr | source |
|---|---|---|---|---|
| firered / leafgreen | `0x03005008` | `0x0300500C` | `0x03005010` | `.sym` |
| radical_red | `0x03005008` | `0x0300500C` | `0x03005010` | ROM `SetSaveBlocksPointers` pool (ROM file `0x4C08C`); `pokemon_storage_base` `0x02029314` stays from `profile.ram` |

`0x03003840` / `0x03003838` are **not** pointer variables. They sit inside `IntrMain_Buffer`
(`src/main.c:80`, filled at `:347-349` by `DmaCopy32(3, intr_main, IntrMain_Buffer, ...)` from the
blob at ROM `0x08000248`) and hold literal-pool constants of the code embedded in that blob —
`0x03003840` is `&gSaveBlock1` (`0x0202552C`) and `0x03003838` is `&gSaveBlock2` (`0x02024588`).
They read correctly on this build only because the offset is 0, so the constant equals the live
pointer; on an FR state (offset `0x74`) the same word is `0x74` bytes behind the live
`gSaveBlock1Ptr`. The old client still ships them for parity (recorded in
`data/games/gen3_rr/profile.json` `_src.ram.SB1_PTR_ADDR`); the checkpoint and every new-client
read use the ROM-derived addresses instead.

`safety.lua` re-checks the setter itself: `anchors.saveblocks_setter` pins the whole function and
its pool per artifact, so a build that moved the setter — or that restored the relocation mask —
is refused at runtime, not only at generation time.

Rule (PLAN §5.3): dereference all three at arm time, keep the snapshot, and compare before every
write. A changed pointer aborts the write; it does not retarget it.
