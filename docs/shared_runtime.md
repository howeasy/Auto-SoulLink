## The portability test

For every item ask: **can Gen 3 bind it without inheriting Gen 1 game facts?** A reusable idea inside a Gen 1 module is not a shared interface today. Track B explicitly calls these **Gen 1 modules containing reusable mechanisms**, with no extraction before the tag: a second consumer must define the real interface rather than inherit a renamed dependency (`prep/PLAN_v3.9.md:874-887`).

### Sync-command lifetime: shipped

**Corrected from the drafting baseline: this has landed, not pending.** The contract is that keyed `party_mon`, `box_mon` and `memorialize` remain **in flight after reply delivery**, until a matching keyed acknowledgement resolves the operation or `SYNC_INFLIGHT_RECONCILES` (= 6, `server/state.py:59`) reconciler passes expire its suppression window. Delivery is not execution. This protects the interval during which a client's deferred write queue still owns the key.

At HEAD, `SoulLinkState.sync_inflight` tracks `(key, cmd) -> passes_remaining` per player (`:152`). `handle_event` drains and clears the player's outbound queue and immediately arms the delivered `SYNC_COMMANDS` entries into `sync_inflight` (`:413-415` calling `_arm_inflight`, `:2267-2271`). Any event that carries a `key` acks every in-flight entry for that key, whatever the event type (`:277-278` calling `_ack_inflight`, `:2273-2277`) — `stats_cache` therefore also acks the window even though it is not itself a positive deposit/withdraw result (see below). `_expire_inflight` spends exactly one pass per key, and only when `_reconcile_party_keys` actually reconciles rather than skipping a pass for an active rebuild or in-flight trade (`:2279-2290`, called at `:2348`). `_has_pending_command` (`:2292-2299`) is what the reconciler consults before treating a key's transient party/box placement as drift — at `:2356-2357`, `:2379-2380` and `:2394-2395`.

Existing keyed completion paths are `sync_retrieve_done`/`sync_retrieve_failed` (`server/state.py:332-366`), `box_mon_failed` (`:369-381`), and memorial completion/failure dispatch (`:383-386`). `stats_cache` is a cache/party-model update (`:318-330`), not a generic positive execution acknowledgement of the deposit itself — but as noted above it does retire the in-flight window for its key through the generic key-carrying ack path, since that path acks on any event that names the key rather than only on the SYNC_COMMANDS' own named replies.

## Adapter-owned game facts

The game binding owns species and item identities, key formats, evolution families, gift/static/area semantics, encounter data, trainer identities, native UI capabilities and party/blob contracts. Its Lua binding additionally owns ROM sites, bank/domain/register interpretation, RAM and SRAM addresses/layouts, serialization, write-checkpoint predicates and cartridge capabilities. None of these become generation-neutral merely because they are injected as JSON.

The concrete rewrite modules and harness contracts are specified in the following sections.

The rules interface pins gift policy (`server/adapters/base.py:61-124`), evolution/gender/types/shininess/identity (`:126-173`), rival ids and party-blob size (`:188-218`), and status/native-panel capabilities (`:232-264`). Track B P8-0's `native_trade_ui()` has shipped (`server/adapters/base.py:281`, default `False`; commit `eef6a1c`): it replaced the six `game_id == "gen1_rby"` branches in the shared trade FSM. The Gen 1 adapter returns `True` for the Red/Blue variants and `False` for Yellow (`server/adapters/gen1_rby.py:351-353`), consistent with `supports_info_panel()`.

### Witness caveats that must survive regeneration

The baseline checker explicitly logs `saves=0 skipped` for a result phase without any save marker (`tools/e2e_duo.py:3255-3259`, `:3271-3277`). That is absence of a witness claim for that phase, not proof that it saved, nor permission for a required-save scenario to omit its SAVE. The plan requires both admission halves to SAVE and separate reconnect phase provenance (`prep/PLAN_v3.9.md:261-276`).

The plan requires removing leftover attempt witness files at attempt start (`prep/PLAN_v3.9.md:720-727`). This freshness requirement is not established by the inspected witness checker, which checks path/size/hash but no mtime (`tools/e2e_duo.py:3286-3308`); integration must verify attempt-start deletion before publishing it as implemented. The runner also names `sMainDataCheckSum` at `$3523` as a post-hook write in mismatch diagnostics (`tools/e2e_duo.py:595-599`, `:3313-3321`). Keep exact byte equality; diagnose the capture boundary instead of masking the checksum.

## Release boundary

No rewrite mechanism is lifted solely for this tag. Gen 3's second binding is the test of the abstraction: provide its sites, CPU/domain/register model, write predicates, layouts, UI ABI and saved-state discovery/qualification/decode, then identify the mechanism that truly remains unchanged. Existing shared server/connector/HUD changes still need Gen 3 trade/faint verification on the final tree (`prep/PLAN_v3.9.md:890-901`). This draft does not claim those runs occurred.
