So with any exec hook, the frame boundary moves to the IRQ entry: R15 = 0x1C = vector 0x18 + 4 (mGBA's PC
after ARMRaiseIRQ, before the handler's first instruction), R14_irq = 0x1C4, SPSR = the System-mode halt's
CPSR. The census park (System, R15 0x1C4) is the same instant seen before the IRQ is taken. This matches W9's
receipt (7d730a89, R15=1C CPSR=20000092 with the full client).

Conclusion: RR (CFRU) idles in SWI 2 Halt. The HALTCNT write is strb @0x1BC; the IRQ that ends the halt is
taken with the next instruction 0x1C0 (bx lr), so R14_irq = 0x1C0 + 4 = 0x1C4, and irqBase returns with
subs pc, lr, #4 to 0x1C0. The admitted IRQ shape (write_checkpoint radical_red.cpu.irq_entry): mode 0x12,
ARM, R15 in {0x1C}, R14 in [0x1B8, 0x1C4], i.e. R14 - 4 inside Halt's body 0x1B4..0x1C0. Any R14 outside
(ROM/RAM game code, the SWI dispatcher, IntrWait's halt @0x1F0 -> R14 0x1F8, not witnessed on RR) is refused.
BIOS-independence of the safety argument: R14 in 0x1B8..0x1C4 means the interrupted instruction was in the
BIOS region, which game code cannot execute from, so no game write can be mid-way; with a different BIOS the
addresses would simply not match and the frame would be refused (fail-closed).
