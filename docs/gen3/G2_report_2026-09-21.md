## 8. Instrument findings fixed on the way

- **Battery naming rule**: BizHawk names the battery file after the gamedb entry when it
  recognizes the ROM (e.g. `Pokemon - FireRed Version (USA).SaveRAM`), and after the ROM's own
  filename with underscores turned to spaces otherwise (`gen3 slink RR.SaveRAM` for
  `slink_RR.gba`). `saveram_name()` now defaults to the underscore→space rule; a gamedb-known
  cartridge still needs `--saveram-name` passed explicitly. Getting this wrong seeds the fixture
  where BizHawk never looks and produces a silent "erased battery at boot" failure.
- **The 14-sector wait**: the flash save counter advances roughly 950 frames before the sector
  write loop actually finishes (mGBA flash timing runs ~66 frames/sector); a driver that flushes
  at the counter alone captures a torn slot (observed: 11/14 sectors, status ERROR). The
  boot-check driver now waits for all 14 sectors of the new slot before flushing.
- **memory_gba.lua substruct permutation bug**: `lua/memory_gba.lua:622` had substruct rows 3 and
  4 swapped versus pret `src/pokemon.c`'s `SUBSTRUCT_CASE(3,0,3,1,2)`/`(4,0,2,3,1)` — vanilla FRLG
  only, affecting PID%24 in {3,4} (wrong moves/ability substruct decoded; species unaffected).
  Fixed (two rows); `tests/unit/test_gen3_lua_vs_codec.py` is now the standing differential guard
  against this class of bug recurring.
