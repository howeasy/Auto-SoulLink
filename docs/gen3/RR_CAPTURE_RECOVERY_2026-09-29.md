The shared client's `capture_wild` hook sets `st.flags.acquire` and `caught`. Before this change, `settle()` cleared `st.flags` *before* checking `recovery_hidden()`. A transient hidden journal read could consume the one engine signal without reading the new party or sending `capture`. The fast RED replay uses the real Lua `gen3_rr` client through `tests/unit/gen3_world.py`, with a visible two-mon baseline, an empty journal whose read is busy for two frames, a real `capture_wild` site fire, and a new third party record. The corrected client retains observer flags only while the journal has a transient busy read, has no failure, is bound to the run, and no native trade has posted. An unsettled trade or corrupt journal discards those flags while keeping the party hidden. The save-site host flush is one-shot for each engine save signal; a later distinct save still flushes again. When the ordinary busy read clears, `settle()` consumes the retained flags against the current party. The test also covers `mon_given` and `pc_move`; each emits exactly one capture TX after visibility returns and no duplicate after 35 more frames.
