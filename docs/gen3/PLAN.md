## 1. Context — why

The Gen 1 rewrite (local master, GATE PASSED 19/19) is the project's real code contract: composition root over injected io/net/hud, engine events from byte-verified execution sites, one armed write gate behind a source-established checkpoint, profile-driven reads with an independent Python codec, fail-closed release runner, duo verdicts from saved-state oracles. pureRGB proved a second foundation binds it. The owner wants the generalized runtime and Gen 3 is the next binding (`docs/shared_runtime.md`: "can Gen 3 bind it without inheriting Gen 1 facts").

Gen 3 today is the protocol's reference implementation (`docs/protocol.md:11`) but the structural opposite: one 4529-line script with a ~2600-line frame handler (`lua/clients/gen3_frlge_client.lua:1853-4476`), polling and PID diffing instead of sites, writes behind per-caller guards in four files, a pattern scraper instead of `json_codec.lua`, hello on TCP connect without admission, and duo verdicts that are the client's own `RESULT:` line (`tools/e2e_duo.py:4134-4153`). It also has the largest feature surface in the repo (RR companion patch: mailbox ABI, native storage/trade/menus/messages, peer ghost, explode, rival swap). Hence strangler, not rewrite.

## 2. The Gen 1 contract, distilled

1. **Composition root** — `Entry.PACKS`/`PACK_FILES` literals, `Entry.admit` (sha1 → anchors → named-family fallback), `Entry.build(deps)` → `(client, parts)`; the only file naming a foundation. `lua/gen1/entry.lua:44-83, 229-266, 300-380`.
2. **Thin bootstrap** with guarded `onframeend`/`onexit`. `lua/gen1/run.lua`.
3. **Client = state machine over injected parts**, no BizHawk globals, `pcall` per handler; hello gated on live save + checkpoint-or-battle; validate/pause never drops queues; deferred FIFO one-per-frame at the checkpoint with keyed `_done/_failed`; retry-at-tail only for `party full` / `last party mon`. `lua/gen1/client.lua:135-167, 298-339, 667-751, 1653-1725`.

5. **One armed write gate** — reason, optional whole-range allow predicate, validate-before-first-byte, provenance log; operation-specific arm reasons (`battle_intro`, `overworld`, `battle_loop_head`, `trade_overlay`, `panel`, `apex_commit`, `transform`). `lua/gen1/writes.lua:54-86`.
6. **Read-only checkpoint predicate** re-verifying ROM anchors every call, fail-closed. `lua/gen1_write_safety.lua:23-109`.
7. **Profile-driven reads** + the one glyph table; Python codec twin as PYDEC oracle. `lua/gen1/reads.lua:71-122`, `server/adapters/gen1_codec.py`.
8. **Pack files named literally**; release manifest derived from them (`tools/make_release.py:126-128`, `tests/unit/test_make_release_manifest.py`).
9. **Adapter** implements `GameAdapter` with opt-in capabilities; no `game_id ==` branches in shared code. `server/adapters/base.py:64-622`.
10. **Two unit layers** — Python vs pack/codec; lupa driving the production `Entry.build` graph against a fake BizHawk + `protocol_schema.py` (`tests/unit/test_gen1_client.py:52-99`).
11. **Launcher routes before `game_detect`** (`lua/slink.lua:63-95`).
12. **Harness** — battery-boot fixtures qualified by the codec, save witness inside the save site, post-result oracle required per scenario for the `gen1_new` family (Gen 2/3 rows still take the legacy client-RESULT path, `e2e_duo.py:4142-4147` — the rule must be extended to `gen3_*` rows), lane isolation, idle jitter. `tools/e2e_duo.py:667-680, 1354-1421, 4040-4153`.
13. **Fail-closed release runner** (allow-listed skips, requirements map: `tools/verify_gen1_release.py:69-86, 98-237, 279-294`) and a ledger with Pins / Oracles / `S·M·P` rows / "Not in this release" / "Recorded limits" (`docs/gen1_requirements.md`).
14. **Wire contract** `docs/protocol.md` §9 (47 items); `tests/unit/test_protocol_conformance.py` is named there and does not exist.

Corrections already honoured: Gen 1's pack is not uniformly generated (RBY `write_checkpoint.json` is hand-pinned; `continue_sites`/`wild_encounter_sites` are RC assets; `gen_gen1_area_map.py` is the pureRGB generator) — the requirement is per-artifact provenance. `test_gen1_no_hardcoded_addresses.py` scans driver scripts only. `stats_cache` acks the in-flight window for its key (`server/state.py:281-285`); delivery ≠ execution.

## 5. Design decisions (each with the review finding it answers)

### 5.1 Packs, admission, pairing (F9)
- `gen3_frlg`: titles `firered`, `leafgreen`; `rom_type` unchanged (`server/adapters/__init__.py:39-41`); kinds `clean` (US 1.0 sha1) and `named` (BPRE/BPGE header, unknown sha1 → vanilla pack by header, then refused by the site check if bytes differ; `lua/gen1/run.lua:37-49` precedent).
- `gen3_rr`: title `radical_red`; `rom_type` `firered_rr`; kinds `clean` (RR 4.1 base) and `companion` (SLink-RR.ups applied). `profile.native` carries every mailbox/ghost/calc address so `native.lua`/`ghost.lua` have no literals.
- **Pairing policy (durable, canonical)**: the foundation is **derived**, never trusted: `foundation_for_rom_type(rom_type)` in `server/adapters/__init__.py` (firered/leafgreen → `gen3_frlg`; firered_rr → `gen3_rr`; Gen 1 packs already differ by game_id). Nothing new is persisted: `rom_type` already is (`state.py:3273-3278`, reload `:895-920`), so a server restart re-derives the lock. Hello `foundation` is optional: absent ⇒ derived (the old RR client keeps working during P4 coexistence); present and ≠ derived ⇒ refused. Kind normalization becomes an adapter hook `pairing_kind(kind)` on `GameRulesAdapter` (default = today's `{"named": "clean"}` rule at `server.py:502-510`; `Gen3Adapter` adds `companion → clean`), so Gen 1 named/clean and pureRGB clean/overlay rules are untouched and `set_artifact_kind` still receives the declared kind (`server.py:1700-1707`; pureRGB `native_trade_ui` depends on it, `gen1_purergb.py:216-227`). `_mixed_games_error` compares derived foundation + pairing kind and runs **before** adapter reselection and connected-player capability updates (`server.py:1260-1304`); a refused hello leaves committed rules, caches and persisted bytes unchanged (the test asserts on-disk `links.json` bytes and the presentation caches). The `key_change` presentation-migration guard (`server.py:1957-1960`) is not touched. **Adapter binding for the comparison**: `pairing_kind` is evaluated as a pure lookup against the *incoming* foundation's adapter class (from the registry, by derived foundation, never by installing a candidate) and the *committed* foundation's adapter; an unknown `rom_type` is refused: today `game_id_for_rom_type()` returns `None` for it (`server/adapters/__init__.py:96-101`) and the call site absorbs that with `or self.adapter.game_id` (`server.py:428`), silently reusing the installed adapter for the wrong foundation; `get_adapter` itself raises `KeyError` (`__init__.py:20-28`). `set_artifact_kind` keeps HEAD behaviour for Gen 1 (`named → clean` normalized before commit, `server.py:1700-1707`); for `gen3_rr` the committed kind is the declared `companion` and only the pairing comparison maps it to `clean`. Tests: companion-first startup with the default adapter, reverse arrival order, persisted-companion restart, unknown type, contradictory foundation. Scheduled as **P3a (mandatory)**; P3's shadow runs do **not** depend on it (the observer sends no hello).
- Manager: `gen3_ap` and `gen3_e` rows (`server/manager.py:61-76`) stay but are labelled "not admitted by the SLink client yet" in P4 (manager.py label only); the client refuses with a named reason on console + HUD.
- `emerald`/`ap` profiles remain in the packs as unadmitted titles.

### 5.2 Signal contract on GBA (F2)
- A site record carries `address` (even Thumb address, no `|1`), `capture_offset`, `expected_hex`, `rom_offset`, `point`, and `mode` (`thumb`/`arm`). At fire, `signals.lua` asserts the **callback address** equals `address + capture_offset` and records `raw_r15`, `cpsr` (mode, T bit), `frame`, `sp` separately; the Gen 1 `register("PC") == pc` assertion is replaced by the callback-address assertion.
- P1 probe matrix (positive and negative): exec hook at `RETURN_FROM_BATTLE_ADDR` (`0x08015B59`, `games/gen3_frlge.lua:85`) and at a site inside a Thumb function body; write hooks at byte/halfword/word starts of the mailbox opcode slot, interior-byte registration (expect loss/duplication as documented), pre-store observation check, natural vs host-initiated write, reset + unregister, wrong-address negative control never fires, `emu.framecount()` in-hook equals the armed frame, and a **capability-budget load test** with a provisional list of ~12 candidate addresses (P1's own list; the pinned full-site load test is a P3 prerequisite once P2 has the packs). Any site whose exec hook cannot be made to deliver is classified **OPEN** (not silently replaced by a write hook); a write-hook site is only accepted with its own positive/negative receipt.
- Callback parameters (`addr`, `val`, `flags`) availability on this host is recorded in the probe receipt, not assumed.
- **PHYSICAL hook probe (P1, 2026-09-21, `docs/gen3/probes/hooks_{fr_clean,rr_companion}_2026-09-21.txt`, `tests/live/test_gen3_probe_gates.py` 2 passed)**: on FR US 1.0 and RR companion (`bf8e94a0…`) rows a (exec at `0x0800051A`, 30/30 frame hits, callback addr == next instruction, raw R15 `0x0800051C` recorded separately), b-base (write hooks deliver, pre-store bytes visible), c (host `memory.write_u8` does not fire the callback), d (unregister/reset: 0 hits after removal, liveness control 60), e (negative control 0 hits), g (`SRAM` 131072 = flash; scopes include System Bus; `event.can_use_callback_params` true) all PASS; a-return OPEN (no battle in the run), b-interior OPEN (interior-byte watches got 0 hits: register at canonical starts), f informational: RR `OPEN sites=12 registered=true frames_off=600 frames_on=600 fps_off=120.0 fps_on=120.0 wall_clock_resolution_s=1 instruction_walk_UNVERIFIED=true`; FR `OPEN sites=12 registered=true frames_off=600 frames_on=600 fps_off=120.0 fps_on=120.0 wall_clock_resolution_s=1 instruction_walk_UNVERIFIED=true`. Every registration id was a non-null GUID.


### 5.3 Checkpoint predicate (F1)
A SOURCE obligation, not an observation: P2 produces a **writer inventory** for each supported build — every code path that mutates party, PC storage, SaveBlock pointers, flash, or the mailbox arena: script commands (`ScrCmd_*` givemon/takemon/setflag...), storage system, save (`WriteSaveBlockChunks`/`HandleWriteSector`), link/cable club, daycare, evolution, level-up/exp tasks, in-game trade, RR heap relocation on battle/map/return (`BR:docs/rr_reference/GAME_HEAP_RESERVATION.md:46-55`), and the companion's own handlers. The predicate is then defined as **"no inventory member is in progress"**, expressed with observable state:

### 5.4 Adapter: no split, plus the compatibility contract (F9)
`Gen3Adapter` keeps answering RR capabilities per instance; the two existing `is_rr` branches in `server.py` stay (they select the adapter and gate the calc). The defect to fix is compatibility, not class naming: §5.1's pack-aware `_mixed_games_error` + hello `foundation`. The **keyed sync-command lifetime stays as shipped.** `SYNC_INFLIGHT_RECONCILES = 6` is by design a *re-issue suppression window, not an ack deadline* (`state.py:45-59`): a client may hold a command until the game is in a state where it can run it, the reconciler may then re-issue, and "the client's already-in-party path absorbs the duplicate"; the window ages out so a dropped answer cannot disable drift repair. The Gen 3 client therefore does what Gen 1 does: keyed commands are **idempotent** (`party_mon` for a key already in the party ⇒ `sync_retrieve_done`; `box_mon` for a key already boxed ⇒ ack; duplicate `memorialize` deduped — protocol §9 items 29-31), `stats_cache` carries the pre-deposit snapshot taken before party-only fields are zeroed (old client `:1613-1633`) and its `party_keys` guard (`:325-338`) is untouched. No `sync_pending`, no server change. Recorded limit (§10): a hold longer than six reconciler passes can produce re-issue churn and, because the reconciler may then issue the **opposite** command to the partner (`state.py:2362-2397`) while the old client cancels queued opposing commands (`:858-882`), a pair can transiently sit in opposite locations or a user deposit can be undone; convergence without record loss is the claim, "never corruption" is **not** asserted. The lupa test therefore holds `box_mon` beyond six passes with ticks and same-key traffic, injects the resulting opposite `party_mon`, runs both execution orders and a reconnect, and asserts quiescent convergence with no lost or duplicated mon record, exact metadata/stats preservation and an explicit final-location policy; persistence is proven by the duo `boxsync` lane's save/reload, not by the World. Pending holds are visible: the client reports `pending` reason/age in its tick HUD line so a stuck queue is diagnosable, and §5.5's liveness bound catches an executor that never uses a safe opportunity.
