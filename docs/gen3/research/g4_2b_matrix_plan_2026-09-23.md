## 5. Receipt and falsifier rules

1. Each sample names ROM/fixture/pack/full source hashes, title, reason, map/position, frame, R15/CPSR, all seven clause values and sorted failed clauses. Include `gBattleTypeFlags`, trainer ID, all controller pointers, comm[0..3], active-party indexes and battle outcome. Record the actual state path/hash and its normal-input preparation receipt. No screenshot-derived fact, memory injection, modified trainer flags, pre-filled party, or write to manufacture an engine phase.
2. A **probe** signs permit/refusal only (`WRITE_SURFACE none`). It cannot claim a production queued mutation, player-visible faint, or persistence. A **duo** signs that stronger behavior through the actual client, keyed real server command, exact write sink/range, independent party/battle readback and normal save witness/PYDEC. Server traffic is the operation under test; it is not a substitute for normal game-state reachability.
3. Queue commands only after a per-phase READY marker; record fresh RX, exact pending cmd/key and attempted-byte count for a hold. A preexisting HP0, wrong key, nonexistent third mon or stale ACK cannot PASS. For an in-battle bench write require HP>0 immediately before, HP0 after, `in_battle` still true and target absent from BOTH active slots. Both player `gBattleMons` must be unchanged by that write.
4. Transient rows need source-state witnesses, not fixed button/frame sleeps. Declare required sampling floors explicitly. If no qualifying phase sample was observed, return UNREACHED/FAIL, never PASS-by-zero-attempts or skip. Auto-running tutorials may offer fewer frames than a parked user menu; an observed named controller sample is more honest than an impossible 180-frame floor.
5. Positive mutation rows must survive a later turn/switch or battle exit and a normal save/reload with matched save-hook/flushed hashes and counter delta. If the target remains in the party, decode its key and HP0. If normal server propagation memorializes it, require that key exclusively in the memorial box and absent from the party; a boxed record has no stored current-HP field, so its persistence does not replace the earlier live HP0 witness. A fixture reload to undo the test is isolation, not persistence evidence. Distinguish game-owned tutorial party swapping/restoration from SLink writes; do not demand byte-identical temporary demo parties.
6. Use full markers and raw per-side RESULT lines from the final receipt machinery. Do not reintroduce the 400-character truncation. Wrong-state and removed-clause tests must actually fail; a static string check is not a first falsifier.
