# P4 old-client inventory: vanilla FireRed/LeafGreen

Source cut: `10cd25f9` in this worktree. This is an inventory of behavior to assess for `lua/gen3/client.lua` on pack `gen3_frlg`, titles `firered` and `leafgreen`. Citations are repository `file:line` at this cut. **SOURCE only:** the old client is a mixed vanilla/RR script, and the P4 release contract takes precedence where the old behavior is defective. The scope is fixed by `docs/gen3/PLAN.md:9-16,139,201,228-236`.

## Inbound commands and effects

All received lines are parsed as a `commands` JSON array by a pattern scraper, then dispatched in array order (`lua/clients/gen3_frlge_client.lua:242-359,1979-1989`). It extracts only the named fields in `:253-354`; unknown commands are logged and `noop` is ignored (`:1049-1050`). The first response is associated with the first sent label by local FIFO, but the label is diagnostic, not a wire acknowledgement (`:1056-1071,1980-1988`). Every outbound acknowledgement below is a normal event with added `player` and monotonically increasing `seq` (`:1059-1065`).

### Queue ordering and safety

The receive path appends keyed commands; a new opposing `box_mon`/`party_mon` filters the old pending opposite, and duplicate `memorialize` is suppressed (`lua/clients/gen3_frlge_client.lua:869-908`). The flush normally peeks the head and removes at most one command per frame, but last-mon memorial may promote a later `party_mon`; a full-party `party_mon` requeues at the tail; exceptions are retried at the front three times then dropped (`:2649-2726`). This is **not strict FIFO** under those exceptions. The server's six-reconcile in-flight window is reissue suppression, not execution proof or an ACK deadline (`docs/gen3/PLAN.md:130-131`; `docs/protocol.md:147-151`).

The old `safe_now` is `is_overworld && sync_cooldown==0 && !party_frozen && post_battle_frames==0 && eob_clear && post_eob_clear`; writes also require `writes_enabled` and no in-flight native mutation/trade (`lua/clients/gen3_frlge_client.lua:2600-2650`). Battle exit arms cooldown and EndOfBattleThings waiting (`:2310-2327`). `M.isPostBattleSettled` checks EOB function, known writer tasks, and evolution callbacks, but the timer can let a write through after 600 frames even when that predicate stays false (`lua/memory_gba.lua:498-534`; `lua/clients/gen3_frlge_client.lua:1518-1526,2620-2626`). More critically, on vanilla `M.isInOverworld()` is just `not M.isInBattle()`, so menus and scripts satisfy the field component (`lua/memory_gba.lua:537-547`). The pack's `data/games/gen3_frlg/write_checkpoint.json` is the P4 authority for a stricter write opportunity; do not reproduce `safe_now` as the new predicate (`docs/gen3/PLAN.md:118-129`).

## Lifecycle and admission limits

The loader detects a ROM profile, applies it, validates RAM plausibility once, and retries validation each frame while `writes_enabled=false` (`lua/clients/gen3_frlge_client.lua:375-393,1864-1876`). `M.validateROM` checks party count, SaveBlock/storage pointers, map bounds and bag IDs; a zero encryption key only logs a warning (`lua/memory_gba.lua:240-318`). Once writes flip on, the old client does **not** revalidate them each frame. It even renames memorial Box 13 as soon as validation succeeds, before a hello or server identity acceptance (`lua/clients/gen3_frlge_client.lua:1870-1885`). This is a write-safety defect, not an admission rule to port.

Every frame pumps TCP; on each connected edge it snapshots the party only if count is 0–6 and the party is not borrowed, seeds known keys from party/boxes, then sends `hello{area_id,loc_name,rom_type,writes_enabled,has_pokeballs,ball_count,badges,trainer_name,party}` (`lua/clients/gen3_frlge_client.lua:1924-1972`). It sends no `ot_id`, `rom_sha1`, `artifact_kind`, `foundation`, or `rom_content`, and sends nothing while disconnected rather than buffering events (`:1059-1065,1950-1957`; `docs/protocol.md:79-96`). `seq` begins at zero per Lua load, increments per sent event, and continues over a TCP reconnect of the same load (`:1056-1065`). A rejected wrong-save hello receives a `hud_show` toast; every later non-hello event is `noop` until a matching hello (`docs/protocol.md:98-113`). The old client has no explicit wrong-save pause or identity-lost handler: it logs unknown `key_change_ack`/`key_change_rejected` and leaves write permission tied only to local validation (`lua/clients/gen3_frlge_client.lua:1049-1050,1864-1876`; `docs/protocol.md:343-344,623`).

The initial snapshot may be empty on the title screen and lacks explicit OT; server identity is then not checked (`lua/clients/gen3_frlge_client.lua:1938-1957`; `docs/protocol.md:106-113`). Party/box keys use personality and OT ID, cached by slot (`lua/clients/gen3_frlge_client.lua:1093-1099`), and a connect seeds non-memorial box keys to avoid interpreting later withdrawals as new captures (`:1846-1862,1945-1949`). Borrowed-party protection freezes diffing and sync while the party PID pattern differs from the stable baseline, then releases on revert, battle end, or timeout; vanilla uses the PID heuristic rather than the RR patch signal (`:1593-1598,3091-3142,3158-3203`). This is an observation guard, not a substitute for save admission.

`safe` is sent once when a post-battle pending flag reaches an overworld state, without a party payload (`lua/clients/gen3_frlge_client.lua:4135-4139`; `docs/protocol.md:135-139`). The ordinary tick runs every 30 frames (`lua/clients/gen3_frlge_client.lua:1489,4141-4149`). The server treats `safe` and `tick` through shared handling, but only a payload with `party` refreshes party keys/blobs (`docs/protocol.md:135-139`).

## Do not port these old-client limits blindly

1. The legacy pattern scraper is not a JSON decoder; it drops escaped strings and nested structures beyond the recognized fields, and its encoder writes empty Lua arrays as `{}` (`lua/clients/gen3_frlge_client.lua:205-239,242-359`; `docs/protocol.md:624`). Bind the existing JSON codec for the new client.
2. A failed `box_mon` sends no `box_mon_failed`; `stats_cache` is sent **before** the deposit, so it does not prove success (`lua/clients/gen3_frlge_client.lua:1641-1679`; `docs/protocol.md:141-151,322`).
3. `party_mon`'s successful-retrieval branch references `ret_base` without defining it in that function; the `pcall(M.readNickname, ret_base)` fails harmlessly and falls back to old label cache, but the new implementation should read the actual retrieved slot (`lua/clients/gen3_frlge_client.lua:1682-1760`).
4. `memorialize_finish` emits `memorialize_done` before returning its verification result, including on a still-in-party failure (`lua/clients/gen3_frlge_client.lua:1764-1790`).
5. The old overworld and post-EOB timeout gates can authorize writes during menus or after an unverified writer task, and memorial Box 13 can be renamed before hello/admission (`lua/memory_gba.lua:498-547`; `lua/clients/gen3_frlge_client.lua:1879-1885,2620-2650`). Use the P2 checkpoint and the armed write gate (`docs/gen3/PLAN.md:118-129`).
6. Old client has no identity rejection state; server wrong-save and key-change rejection are protocol behavior that P4 must handle explicitly (`lua/clients/gen3_frlge_client.lua:1049-1050,1864-1876`; `docs/protocol.md:98-113,343-344,623`).
7. Opposing-command cancellation and the six-reconcile reissue window can cause transient opposite locations; the migration contract promises convergence without record loss, not absence of temporary drift (`lua/clients/gen3_frlge_client.lua:869-894`; `docs/gen3/PLAN.md:130-131,235`).
8. The old client writes companion EWRAM bytes even on a vanilla load if its mailbox module is present; the new FRLG client must have no such eager native side effect (`lua/clients/gen3_frlge_client.lua:145-158,1011-1028`; `lua/mailbox.lua:253-271,283-293`; `docs/gen3_requirements.md:93-98`).
