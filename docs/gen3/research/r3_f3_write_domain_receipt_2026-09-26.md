# R3-F3 receipt: FR/LG write-domain audit (2026-09-26)

Closes the gap in `randomized_gen3_design.md` §5 risk 7(a). It applies pureRGB's T6 standard
(`docs/purergb/PLAN.md` A5 / G5) to FR/LG: disabled settings write nothing, enabled settings write
only inside their allow-listed domains, and 0 bytes land anywhere else.

## What was built

- `server/upr_gen3_write_domain.py`:
  - `domains_for_spec(spec)`: which domains an FR/LG spec enables, using `Randomizer.randomize`'s
    own conditions.
  - `audit()`: diffs the clean ROM against the output. Every changed byte must fall in an enabled
    domain; every stray byte is named by the domain(s) that hold it, or marked `unattributed`.
  - `check_output()`: the pipeline's one call.
  - `build_model()`: builds the data file (see below).
- `data/games/gen3_frlg/upr_write_domains.json`: 38 domains per title. Every component carries a
  `source` naming the fact it comes from. The file is generated by
  `python -m server.upr_gen3_write_domain --write` from three inputs:
  - the pinned jar (sha256 `28292b59...`): its own `gen3_offsets.ini` `[Fire Red (U) 1.0]` and
    `[Leaf Green (U) 1.0]` sections, and its IPS code tweaks, read from the jar;
  - the clean pinned ROMs, walked the way `Gen3RomHandler` walks them (its locators,
    `preprocessMaps`, the wild headers, the trainer table, the ±500-byte text-pointer search);
  - the pret `.sym`, used for the free-space gap.

  A ROM-backed test rebuilds the file and requires it to be byte-equal to the committed one.
- `tools/upr_write_domain_diff.py`: new Gen 3 mode. Example:
  `--title firered|leafgreen --clean C --out O --log O.log`, or pass `--enable DOMAIN` instead of
  `--log`.
- `tests/unit/test_upr_gen3_write_domain.py`: 15 tests (ROM-free model rows plus ROM/jar rows).

## Pipeline wiring (not applied: `server/upr_pipeline.py` is leased elsewhere)

In `prepare_pair`'s FR/LG branch, right after `info["sites_intact"] = True`:

```python
            info["write_domain"] = upr_gen3_write_domain.check_output(sources[player], info["output"], info["spec"])
```

It needs `from server import upr_gen3_write_domain` at the top of the module. The module does
not import `upr_pipeline` at import time, so this creates no import cycle. `check_output` raises
`UprPipelineError` naming the domains the stray bytes fall in.

## Findings for the owner / other lanes

1. **The baseline writes into the forbidden `abilities` and `base_stats` columns, even with every
   setting off.** This is the ability-normalisation blocker from the Codex review; the audit makes
   it explicit rather than fixing it. A test pins that allowed domains meet forbidden tables ONLY
   at these two normalisations. Once the fork stops writing them, drop them from `baseline` and
   that test tightens itself.
2. **`obedience_evo_code` is a CODE write that the 21-site check never covered.**
   `attemptObedienceEvolutionPatches` runs whenever wild, starters or statics are randomized. It
   makes Deoxys and Mew obey and lifts the Kanto-dex gate on level and stone evolution. It is
   allowed today because every default preset triggers it; this is a gameplay change the owner
   may want to rule on.
3. **Trainer repointing is not granted.** No allowed option grows a party. If a future option
   does, the audit refuses it by name instead of passing it silently.

## Not verified

- **Range level only.** The audit does not check values. A pointer written inside an allowed
  domain (for example a TM text site) is not checked for where it points, and free-space
  contents are not validated.
- **Scope.** Only FR/LG 1.0 (U) are covered. FR/LG 1.1, other regions and Emerald are not.
- **Matrix artifacts.** The isolation-matrix runs are scratch outputs and were not kept. The
  committed tests re-run the lossless and all-options cases per title.
