# pureRGB Game Data (PureRed/PureBlue/PureGreen)

Data files for pureRGB v2.7.6, a pret/pokered source fork (`game_id gen1_purergb`), pinned at
commit `7e7a46535ca332ad24ecb02e326ea2f75e79ebb9` (`data/purergb_sources.lock.json`). Generated
the same way as `data/games/gen1_rby/` — source asserts against the pinned checkout plus
byte-verification against the canonical build — never hand-typed. Species throughout this
directory are **internal indices**, not National Dex ids: pureRGB's `PokedexOrder` mapping is
many-to-one (dex 0 covers 39 forms/spirits/unused slots, one of which — `$B5` MISSINGNO — is a
real catchable species), so National Dex is not a stable key here the way it is for vanilla.

## Files

- `area_map.json` — Map id → `{area_id, name}` for all 248 map ids (every id gets an entry,
  unlike vanilla's ~88-row hand-maintained file, since decision 4 requires a display name for
  any map a client can land on). Generated by
  [tools/gen_gen1_area_map.py](../../../tools/gen_gen1_area_map.py) from
  `constants/map_constants.asm` + the wild/fishing tables. Follows owner ruling U10 ("vanilla's
  dungeon collapse"): Mt. Moon, Rock Tunnel, Seafoam Islands, Victory Road, Pokemon Tower,
  Pokemon Mansion, Cerulean Cave, Rocket Hideout and Silph Co. each collapse their floors onto
  one shared area id (matching vanilla's own file, which does the same for these nine
  buildings, not only the five U10 names by example); the four Safari Zone quadrants do **not**
  collapse into each other ("stay one area each"). `Mt. Moon Pokecenter` / `Rock Tunnel
  Pokecenter` keep their own area id rather than folding into an arbitrary floor, again matching
  vanilla. Regenerate with `python tools/gen_gen1_area_map.py`; `--check` verifies without
  writing.
  - **Gift interiors get their own area id** (rule `gift_building_own_area`, recorded in
    `area_map_notes.json`): every table-less map named by `gifts.json` is its own area (78 areas
    after collapse) instead of inheriting the town it stands in — the same thing vanilla does by
    hand for `oaks_lab` / `celadon_mansion_roof` / `game_corner`. A gift must never share an area
    with the wild or fishing table the town carries, or the first gift there would dead-zone it
    (PLAN §2.3); the generator refuses to emit a map where a gift area coincides with an
    encounter area.
- `floor_labels.json` — Map id → floor suffix (`" 1F"`, `" B1F"`, ...) for every map that belongs
  to a collapsed multi-floor area **and** carries its own wild-data pointer (a floor with no
  pointer of its own, e.g. the new `POKEMON_TOWER_B1F` or any Rocket Hideout/Silph Co. floor,
  gets no suffix — same rule vanilla's generator already applies). Consumed by
  `tools/gen_gen1_encounters.py --foundation purergb` to suffix method names ("Grass B1F") and
  intended for a ROM scanner labelling a randomized cartridge's floors, mirroring
  `data/games/gen1_rby/floor_labels.json`'s role.
- `area_map_notes.json` — sidecar audit file (not a runtime contract): every map whose area
  assignment could not be derived from its constant name alone (`game_knowledge_override`) or
  was left as an unresolved fallback, with the rule that fired. Kept **out** of `area_map.json`
  itself — that file's `{"<map_id>": {...}}` shape is indexed by `int(map_id)` in more than one
  consumer, and a stray non-numeric key would break that walk.
- `encounter_tables.json` — Wild encounter tables, keyed by title (`purered`/`pureblue`/
  `puregreen`) then by `area_id`, mirroring vanilla's schema plus two additions: a top-level
  `species_id_space: "internal"` field (species ids in every entry are internal indices, not
  NatDex — call this out explicitly since vanilla's equivalent field is NatDex), and fishing
  methods (`OldRod`, `GoodRod`, `GoodRodOcean`, `SuperRod`) that vanilla's file has never
  carried. Grass/water tables are read from the **built ROM**'s `WildDataPointers` (bank `$2C`)
  and cross-checked against the source parse for all three titles (0 mismatches). MISSINGNO
  rows are kept (dex 0 is a real species here, e.g. Cinnabar Island/Route 19/Route 20's shared
  Sea Routes table). Regenerate with
  `python tools/gen_gen1_encounters.py --foundation purergb`; the default (no `--foundation`, or
  `--foundation pret`) invocation is byte-for-byte unchanged and still targets
  `data/games/gen1_rby/`.
- `static_encounters.json` — Extends vanilla's `gen1-statics-v1` schema. The `statics`/`cites`
  blocks keep vanilla's map-id → internal-species-list shape unchanged (so the client's
  `self.statics[tostring(map_id)]` lookup needs no purergb-specific branch); a new `records`
  array carries the richer per-site facts the task asks for: map id, internal species, level,
  `event_flag` (source-asserted against `constants/event_constants.asm`, `null` where the
  encounter has no repeatable gate), `kind` (`script` or `object_event`), and a `cite`
  (`file:line`). Zapdos and Victory Road's Moltres are each represented at **two** map ids (a
  script/inline site and a separate `object_event` floor site) sharing one species+level+flag,
  matching pureRGB's actual two write sites. Excludes Pokemon Tower B1F's spirits (no species
  write exists for them) and Bill's Garden (a wild encounter, not a static). Regenerate with
  `python tools/gen_gen1_statics.py --foundation purergb`.
- `trainers.json` — New schema (`gen1-purergb-trainers-v1`; vanilla's file is hand-curated, not
  generated). Top level: `opp_id_offset` (197), `rival_ids` (`[221, 237, 238]`), `num_trainers`
  (56), and `classes` keyed by `wCurOpponent` value (198..253) → `{class, name, data_label,
  party_count, grammars, records}`. `name` is `null` for the three rival/champion slots
  (`TrainerNames` ships them as blank strings by design — `GetTrainerName` substitutes
  `wRivalName` at read time). Grammar-aware: each party record is tagged `fixed` (one level
  shared by every species), `FF` (per-species level, no palette bit), `FE` (per-species level +
  alt-palette bit) or `FD` (a custom-moveset id plus per-species level), never counted by a
  naive "how many `db` lines" scan — `JrTrainerMData` wraps one record in
  `IF DEF(_DEBUG)/ELSE/ENDC`, and counting both branches overcounts a release ROM's real party
  pool by one. Cross-checked against the built ROM's `TrainerDataPointers` (bank `$0E`): all 56
  pointers are verified to resolve to the exact `.sym` address of the source label each class
  claims, including the four classes (`ROOKIE`, `FITNESS_GIRL`, `SPRINTER`, `FIST_FIGHTER`) that
  alias `RookieData`. Regenerate with `python tools/gen_gen1_trainers.py`.

## The other files of this pack (M1 first half — profile, sites, checkpoint, admission, species, moves, items, charmap)

- `profile.json` — `tools/gen_gen1_profile.py --foundation purergb`: 179 RAM / 62 ROM symbols per title from
  `data/purergb/*.sym`, `rom_sha1`/commit from `data/purergb_sources.lock.json`, `derived` constants with source
  asserts (`ball_items` [1,2,3,4,5,8], `opp_id_offset` 197, `bag_capacity` 30, `base_stats_stride` 35,
  `dex_count` 152 = dex ids 0..151, `species_count` 190, `rival_trainer_ids` [221,237,238], `hardware` cgb).
- `engine_signals.json` — `tools/gen_gen1_engine_signals.py`: 40 sites per title, each with a source-text assert,
  an operand-shape check resolved from the .sym and `expected_hex` sliced from the built ROM; `address` is the
  anchor, hook = `address + capture_offset` (non-zero only for `bag_received`). Independently fact-checked
  120/120 (docs/purergb/PLAN.md §13 G2).
- `write_checkpoint.json` — `tools/gen_gen1_write_checkpoint.py`: the pure overworld checkpoint
  (`[SP] == DelayFrame+24`, `[SP+2] == OverworldLoop+1`, `wDelayFrameBank == 0`, WRAM bank gate); version
  `gen1-main-loop-purergb-v1` (the client learns per-foundation versions in M2).
- `admission.json` — `tools/gen_gen1_admission_profiles.py`: `{sha1 -> {title, kind, profile_id, header_crc, …}}`.
- `species_index.json`, `types.json` — `tools/gen_gen1_species.py`: keyed by internal id 1..190, 13 non-dex
  records classified, `base_species` for forms, default typings, 9 transform edges; ROM-verified 34/0.
- `evolutions.json` — `tools/gen_gen1_evos.py --foundation purergb`: edge-level like vanilla (76 method entries
  collapse to 72 edges / 79 families; forms resolve their family through `base_species`).
- `moves.json`, `items.json` — `tools/gen_moves_data.py` / `tools/gen_gen1_items.py` with `--foundation purergb`.
- `charmap.json`, `charmap.lua` — `tools/gen_gen1_charmap.py`; the Lua twin carries glyphs/shortcuts/terminator
  only (name lengths come from `profile.derived`). Raw name bytes stay authoritative; decoding is display-only.

## Notes

- Every generator in this directory takes `--foundation purergb` (or, for the two new tools that
  have no vanilla equivalent, always target this directory) and resolves paths through
  `tools/gen1_foundation.py` — no generator here hard-codes a `.cache/pret`-style path.
- `docs/purergb/PLAN.md` §11.2 (`A12`, `A13`, `O3`, `W1`, `W2`) is the verified-facts ledger this
  directory implements; `docs/purergb/research/w1/{encounter_census.json,area_map_purergb.json}`
  is the research-phase draft this pack's generators supersede (that draft does not apply the
  U10 collapse and is not ROM-verified for the area map; the encounter side was already
  ROM-verified 248/248 with 0 mismatches and this pack's own independent ROM walk agrees).
- One documented discrepancy: `docs/purergb/PLAN.md`'s S2 census digit array gives
  `JR_TRAINER_M`'s party count as 11; direct source parsing (respecting pureRGB's own
  `IF DEF(_DEBUG)` branch, which never assembles into a release ROM) gives 10, matching the
  same document's own later prose ("JR_TRAINER_M 10, FISHER 11" in A12). `tools/gen_gen1_trainers.py`
  treats 10 as correct and prints a note rather than failing, since only 4 of the S2 array's 56
  entries were independently ROM-verified and this one was not among them.
